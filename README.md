# Quantum Research

Educational and Research resource for Quantum computing and Quantum information

## Editing and building

Most pages under `research/`, `news/`, `references/`, `tools/`, `education/index.html` and the home page are
generated by `scripts/build.py` from the files in `content/` (each generated page starts with a comment
saying so). Edit the JSON sources, then rebuild:

```sh
python3 scripts/build.py          # regenerate pages; refuses to overwrite pages edited by hand
python3 scripts/build.py --check  # verify generated pages are current (also runs in CI)
python3 -m unittest discover -s tests
```

The Tools section is rendered by `scripts/tools.py` from `content/tools.json`; its interactive
models live beside the pages in `tools/` (the single-qubit explorer is `single-qubit.js` plus
`tools.css`). Course chapters under `education/<course>/` have their own `build.py`. News curation is
described in `content/PAPERS.md`. General-audience articles and homepage selection are described in
`content/NEWS.md`.

GitHub Actions runs the build check and tests on every push (`.github/workflows/checks.yml`) and checks
external links weekly (`.github/workflows/links.yml`; run locally with `python3 scripts/check_links.py`).

## Styles and accessibility

`styles.css` is loaded by every page and owns the design tokens (`:root`, with dark-mode values under
`html[data-theme=dark]`). Use `var(--ink)`, `var(--muted)`, `var(--line)`, `var(--blue)` and the other tokens
instead of hex colours, including in course stylesheets, so both themes and the high-contrast settings keep
working. Its last section holds the shared accessibility rules (focus ring, underlined prose links, reduced
motion, `prefers-contrast`, Windows high-contrast mode).

`tests/test_accessibility.py` checks every page's markup (language, title, one `<h1>`, skip link, alt text,
named links and buttons, labelled form fields, unique ids, zoom allowed), and
`tests/test_palette_contrast.py` checks the token palette against WCAG AA contrast in both themes.

## Shared templates

Content is separate from presentation: `scripts/build.py` renders research pages,
`scripts/news_articles.py` renders the homepage and public articles, and the course
builders render their reader layouts. All three use `education/site_navigation.py`
for **Home · News · Education · Research · Tools**, including relative links and the active
section. `navigation.js` decorates utility buttons only; primary links retain their
visible labels with or without JavaScript.

After changing shared navigation or styles, rebuild the site and course readers
(the Computing build also refreshes its offline download):

```sh
for course in education/*/build.py; do python3 "$course"; done
python3 scripts/build.py
python3 -m unittest discover -s tests
```

## Adding pages and keeping maps current

After adding, renaming, or removing a public page, run its content builder (if any), then `python3 scripts/build.py`. This refreshes both the interactive website graph (`website-map/index.html`) and the search-engine sitemap (`sitemap.xml`) from one shared inventory. Public HTML pages are discovered throughout the site, including new standalone sections and nested pages. Redirects, noindex pages, and build inputs are excluded. Commit the map updates with the page, and run `python3 scripts/build.py --check` before finishing.
