2.1

Boolean Functions

To build computations from operations on bits, we first need a precise description of what is to be computed, independent of how. Encodings reduce every task to a function on bit strings, and truth tables specify such functions completely. A specification is not yet a method, so we then ask how a truth table can be turned into a formula built from a few operations.

2.1.1 Binary encodings§

A computation acts on configurations made of bits. How, then, can it work with numbers, text, or graphs?

We choose an encoding: a rule that writes each object as a string of bits. An integer can be written in binary, text character by character, and a graph as a list of its edges. With two bits, for example, the integers \(0,1,2,3\) become \(00,01,10,11\).

The bits themselves carry no meaning. The string \(01000001\) is the integer \(65\) in binary and the letter A in the ASCII character code. Meaning belongs to the encoding.

Why does the choice of encoding matter? It fixes the length \(n\) of the input, and the cost of a computation will be measured against \(n\). With \(n\) bits there are \(2^n\) possible inputs.

For a fixed length \(n\), a computation is then a function from \(n\)-bit strings to bit strings. A procedure that works for every length is a family of such functions, one for each \(n\), built in a systematic way rather than separately for each length.

2.1.2 Boolean functions and truth tables§

What exactly do we want to compute? Take a yes/no question about an \(n\)-bit input. Its answer is a Boolean function \(f:\{0,1\}^n\to\{0,1\}\), which assigns \(0\) or \(1\) to every input. An answer of several bits is a list of such functions, one for each output bit.

The most direct way to specify \(f\) is to list every input together with its output. This list is the truth table of \(f\). For AND and OR on two bits:

Input \(xy\)ANDOR
\(00\)\(0\)\(0\)
\(01\)\(0\)\(1\)
\(10\)\(0\)\(1\)
\(11\)\(1\)\(1\)

Does a truth table tell us how to compute \(f\)? It tells us what the answer is, not how to obtain it. It also grows quickly: a function of \(n\) bits has \(2^n\) rows, so the table alone is exponentially large. We want a description built from a few simple operations.

2.1.3 Polynomial representation over the binary field§

Can a truth table be turned into a formula? Use arithmetic modulo two, in which \(1+1=0\). Addition modulo two is then XOR, and multiplication is AND.

The idea is to build, for each row \(s\) of the table, a detector that equals \(1\) on the input \(s\) and \(0\) on every other input. The factor \(x_i\) equals \(1\) exactly when \(x_i=1\), and the factor \(1+x_i\) equals \(1\) exactly when \(x_i=0\). Multiplying one such factor for each bit gives

\[\delta_s(x)=\prod_{i:\,s_i=1}x_i\prod_{i:\,s_i=0}(1+x_i).\]

For two bits \((x,y)\), the detector of the row \(01\) is \((1+x)y\).

Now add the detectors of the rows on which \(f\) equals \(1\):

\[f(x)=\sum_{s:\,f(s)=1}\delta_s(x)\pmod 2.\]

Why is this \(f\)? On any input \(x\), exactly one detector, \(\delta_x\), equals \(1\). If the row \(x\) is among those added, the sum is \(1\); otherwise it is \(0\).

For OR, the rows with output \(1\) are \(01\), \(10\), and \(11\):

\[(1+x)y+x(1+y)+xy=x+y+3xy=x+y+xy\pmod 2.\]

Check the row \(11\): \(1+1+1=1\) modulo two, as required, whereas ordinary addition would give \(3\). Expanding the detectors in this way writes every Boolean function as a polynomial in its input bits.

2.2

Boolean Circuits

A polynomial names the operations to perform, but not their order or the values passed between them; a circuit supplies both. We show that circuits compute every Boolean function, reduce the kinds of gate needed to one, and then look at the gates themselves, asking what each one keeps of its inputs.

2.2.1 Polynomial evaluation by circuits§

How do we evaluate \(x+y+xy\) one operation at a time? Compute \(u=xy\) with an AND gate, compute \(x+y\) with an XOR gate, and combine the two results with a second XOR gate.

This arrangement is a circuit. Its gates are elementary operations, and its wires carry bits from one gate to the next; here a wire carries \(u\) from the AND gate to the last XOR gate. A wire may also carry a fixed bit, \(0\) or \(1\). No wire leads back to an earlier gate, so the gates can be evaluated in order.

The same method works for every polynomial: multiply factors with AND gates and add terms with XOR gates. So every Boolean function of a fixed number of bits has a circuit.

Does it have a small circuit? Not necessarily: the polynomial built from a truth table can have exponentially many terms. That every function can be built is one claim; that it can be built economically is another.

2.2.2 NAND universality§

Do we need AND, XOR, and NOT as separate kinds of gate? One kind is enough. NAND outputs the negation of AND, \(\operatorname{NAND}(a,b)=\neg(a\land b)\); it is \(0\) only when \(a=b=1\).

Tying both inputs to the same bit gives NOT: \(\operatorname{NAND}(a,a)=\neg a\). Negating a NAND output gives AND. XOR takes four NAND gates:

\[t=\operatorname{NAND}(a,b),\quad u=\operatorname{NAND}(a,t),\quad v=\operatorname{NAND}(b,t),\quad a\oplus b=\operatorname{NAND}(u,v).\]

Checking the four input pairs confirms the last identity. Since NAND builds AND, XOR, and NOT, it can evaluate the polynomial of any Boolean function. A gate with this property is universal.

In this construction one bit often feeds several gates: \(a\) and \(b\) each feed two NAND gates, and so does \(t\). Copying a bit in this way, called fan-out, is free in classical circuits.

2.2.3 Irreversible Boolean operations§

Given the output of an AND gate, can we recover its inputs? If the output is \(1\), yes: the input was \(11\). If it is \(0\), the input could have been \(00\), \(01\), or \(10\). Three inputs merge into one output, so the map has no inverse. This is logical information loss, and it happens whether or not the gate computes something useful.

Is a circuit irreversible whenever one of its gates is? Not in its overall effect: a circuit can compute a one-to-one function of its input while erasing intermediate values along the way. Its truth table is then reversible, but its individual steps are not. Whether information is lost is a question about each step, not only about the overall truth table.

2.3

Information Erasure

Logical information loss has a physical side, because every bit is held by a physical system. We find the minimum cost of erasing a bit, separate it from other sources of heat, and ask whether it can be avoided altogether. It can, by a construction that keeps the input beside the answer.

2.3.1 Landauer’s principle§

Does losing information cost anything physically? A bit is stored in a physical system, such as a capacitor that is charged or uncharged. Resetting an unknown bit to \(0\) merges two physical possibilities into one.

Landauer’s principle states that erasing a bit that is equally likely to be \(0\) or \(1\), at temperature \(T\) and without keeping a record of its value elsewhere, releases on average at least \(k_{\mathrm B}T\ln2\) of heat into the surroundings. Here \(k_{\mathrm B}\) is Boltzmann’s constant.

The conditions matter. A bit already known to be \(0\) can be left alone at no cost. A biased bit, or a bit whose value is recorded elsewhere, carries less uncertainty and needs less. The principle is not a fixed charge on every gate; it is a lower bound on the cost of destroying information.

The information lost by AND, or by a reset, therefore has a physical counterpart: heat.

Further detail: Bennett: Landauer’s principle and reversible computation.

2.3.2 Logical reversibility and dissipation§

If a computation never erases information, does it produce no heat? Not necessarily. A logically reversible map, one that is one-to-one on its allowed states, avoids the cost that erasure forces. A real device may still dissipate energy through resistance, friction, imperfect control, or the speed at which it runs.

Conversely, can a gate that loses information be made reversible by operating it slowly? No. Running AND slowly does not make its output reveal its input. Reversibility is a property of the map, not of how the map is carried out.

Two questions must therefore be kept apart: whether the mathematical map can be inverted, and how much energy its physical realization uses. For quantum computation the first question is decisive, because the operations of an isolated quantum system can always be inverted.

2.3.3 Reversible function embeddings§

Can every function be computed without erasing information, even one such as AND that merges its inputs? It can, provided we keep the input.

Add a target bit \(t\) and replace \(f\) by the map

\[U_f:(x,t)\mapsto(x,\,t\oplus f(x)).\]

The input \(x\) is kept, and \(f(x)\) is added to the target modulo two. With \(t=0\), the target becomes the answer \(f(x)\).

Why is this map reversible? Apply it twice: \(t\oplus f(x)\oplus f(x)=t\), because adding the same bit twice modulo two gives zero. The map is its own inverse. For AND it is \((x,y,t)\mapsto(x,y,t\oplus xy)\):

\((x,y,t)\)\((x,y,t\oplus xy)\)\((x,y,t)\)\((x,y,t\oplus xy)\)
\(000\)\(000\)\(001\)\(001\)
\(010\)\(010\)\(011\)\(011\)
\(100\)\(100\)\(101\)\(101\)
\(110\)\(111\)\(111\)\(110\)

Has AND become invertible? No: \(f\) itself is unchanged and still merges its inputs. What is invertible is the larger map, whose output keeps \(x\). The extra bits are not mere bookkeeping; they are what makes the transformation one-to-one.

2.4

Reversible Gates

A reversible embedding exists for every function, but we still need gates that carry it out. We look for the simplest gates that change a bit without losing anything, find which of them suffice for every Boolean function, and then deal with what a long reversible computation leaves behind.

2.4.1 Controlled reversible operations§

How can a gate act on one bit depending on another without losing anything? Keep the deciding bit unchanged, and let it choose a reversible update of the other bit. The kept bit is the control; the updated bit is the target.

The simplest example is controlled-NOT, or CNOT: \((a,b)\mapsto(a,b\oplus a)\). When the control \(a\) is \(0\), the target is unchanged; when \(a\) is \(1\), the target flips. So \(00\to00\), \(01\to01\), \(10\to11\), and \(11\to10\).

Applying CNOT twice restores both bits. Why does this work? The control survives the gate, so we know which update was applied, and each update, doing nothing or flipping, is its own inverse.

Would it be enough to make the target update reversible but discard the control? No: without the control we would not know whether to flip the target back.

2.4.2 CNOT, Toffoli, and Fredkin gates§

Is CNOT enough to build every reversible computation? Each bit produced by CNOT and NOT gates is a sum modulo two of input bits, possibly plus \(1\). Such gates can therefore never produce the product \(xy\).

The Toffoli gate adds a second control: \((a,b,c)\mapsto(a,b,c\oplus ab)\). With its target starting at \(0\), it writes the AND of its controls while keeping them. With a control fixed at \(1\) it acts as CNOT, and with both controls fixed at \(1\) as NOT. Since AND and NOT suffice for every Boolean function, Toffoli gates, together with extra bits set to fixed values, can compute every Boolean function reversibly.

Is the Toffoli gate the only choice? The Fredkin gate keeps one control and swaps two targets when the control is \(1\). With the second target fixed at \(0\), it sends \((a,b,0)\) to \((a,\,b\land\neg a,\,ab)\): it too writes the AND, and so it too computes every Boolean function reversibly. Toffoli and Fredkin gates are each their own inverse.

In circuit drawings, a filled dot marks a control that acts when it is \(1\), a circled plus marks a target that is updated by XOR, and a vertical line joins the parts of one gate.

2.4.3 Workspace and uncomputation§

Toffoli gates compute every function reversibly, but a longer computation produces intermediate results along the way. What becomes of them? Compute the AND of three bits \(x,y,z\) with Toffoli gates, using two extra bits that start at \(0\): a workspace bit \(w\) and an output bit \(t\). The first Toffoli gate writes \(w=xy\); the second, with controls \(w\) and \(z\), writes \(t=xyz\):

\[(x,y,z,0,0)\to(x,y,z,xy,0)\to(x,y,z,xy,xyz).\]

The answer is in \(t\), but \(w\) still holds \(xy\). What should we do with it? Resetting \(w\) to \(0\) erases it, with the cost of erasure. Leaving it means that the workspace keeps a record of the computation’s history, and every further computation adds more.

There is a third option: apply the first Toffoli gate again. It is its own inverse, so it returns \(w\) to \(xy\oplus xy=0\):

\[(x,y,z,xy,xyz)\to(x,y,z,0,xyz).\]

This is uncomputation. In general, a reversible computation of \(f\) produces its answer together with intermediate values \(g(x)\), often called garbage. Copy the answer into a fresh register with CNOT gates, then run the computation backward:

\[(x,0,0;0)\to(x,f(x),g(x);0)\to(x,f(x),g(x);f(x))\to(x,0,0;f(x)).\]

Only the input and the copied answer remain. Why go to this trouble? Classically, it avoids the cost of erasure. Quantum computation adds a stronger reason: leftover records of a computation’s history prevent the interference on which quantum algorithms depend.
