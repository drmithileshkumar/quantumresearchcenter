3.1

States and Transitions

Deterministic, nondeterministic, and probabilistic computations look different. To compare them, we first describe what we know about a register at a given time, its state, and find that all three kinds of knowledge take the same form. We then ask the same question under each kind of rule: from a given start, where can a two-step run end? Doing the calculation three times shows what the three kinds of rule have in common.

3.1.1 States§

Take a register holding one bit. Its possible contents, \(0\) and \(1\), are its configurations. At any moment the register holds exactly one of them.

Do we always know which? We may have set the bit ourselves, and then we know it. We may know only that either configuration is possible. Or the bit may have been set by a fair coin, so that each configuration has probability \(1/2\). What we know about the register at a given time is its state.

All three kinds of knowledge take the same form: a number \(v_j\) for each configuration \(j\), its weight in the state.

What we know\(v_0\)\(v_1\)
The bit is \(0\)\(1\)\(0\)
Either value is possible\(1\)\(1\)
A fair coin set the bit\(1/2\)\(1/2\)

The weights mean different things in different rows. A weight \(1\) or \(0\) records whether a configuration is possible; a probability records how often it occurs. A state with weight \(1\) on one configuration and \(0\) on the others is definite, and we name it by that configuration.

3.1.2 Transitions§

A computation changes the register step by step. A transition rule says which configurations may follow each one. As an example, take NOT, which flips the bit.

We draw a rule as a state diagram: a circle for each configuration, and an arrow \(i\to j\) whenever the rule lets \(j\) follow \(i\). Each arrow carries a weight. For NOT every weight is \(1\), because the step certainly follows the arrow.

Applying a rule step by step produces a run \(c_0,c_1,c_2\), where \(c_t\) is the configuration after \(t\) steps. From \(0\), NOT gives \(0,1,0\). To see a run in a diagram, copy the configurations once for each time \(t=0,1,2\) and join the copies by the arrows of the rule. In this time-expanded diagram, a run is a path from time \(0\) to time \(2\).

Rules differ in how many arrows leave each configuration and in what their weights mean. These two differences separate the three kinds of rule that follow.

3.1.3 Deterministic transitions§

Compare NOT with RESET, which writes \(0\) whatever the bit holds.

ConfigurationNext under NOTNext under RESET
\(0\)\(1\)\(0\)
\(1\)\(0\)\(0\)

From \(0\), NOT gives the run \(0,1,0\) and RESET gives \(0,0,0\). Under both rules, exactly one arrow leaves each configuration, so the start fixes the whole run: both rules are deterministic. From a definite state, the state stays definite at every step.

Can a run also be traced backward? Under NOT, exactly one arrow enters each configuration, so the previous bit is always known. Under RESET, two arrows enter \(0\), and a run that reaches \(0\) may have come from either bit. A deterministic rule with exactly one arrow entering each configuration is reversible.

3.1.4 Nondeterministic transitions§

Nondeterminism relaxes the requirement of a unique successor. A configuration may have several permitted successors, so specifying the present no longer specifies a unique future. The rule describes a set of possible runs rather than a single run.

For a bit, consider KEEP-OR-FLIP: from either configuration, both \(0\) and \(1\) are permitted. Its state diagram has all four arrows. Starting from \(0\), two steps admit four paths:

\[0\to0\to0,\qquad0\to1\to0,\qquad0\to0\to1,\qquad0\to1\to1.\]

A path is possible when every transition along it is permitted. A configuration is reachable when at least one possible path ends there. Both zero and one are therefore reachable after two steps. In a nondeterministic model of computation, acceptance is defined in the same way: an input is accepted if at least one permitted run accepts it.

This is a statement about possibility, not a mechanism for choosing among paths. Even if more paths reached one endpoint than another, the rule would not make that endpoint more likely. Counting possibilities and assigning probabilities are different tasks. To predict how often a future occurs, we need more information on the arrows.

3.1.5 Probabilistic transitions§

A probabilistic rule supplies the information that nondeterminism leaves unspecified: the probability of each next configuration, given the present one. We write the probability on an arrow \(i\to j\) as \(P(j\mid i)\), read “the probability of \(j\) given \(i\).” Since some next configuration must occur, the probabilities leaving each configuration add to one.

The current configuration is assumed to contain all the information needed for this prediction. If earlier history matters, that history must be included in the configuration. With this assumption, the process is called Markov.

Consider COIN: whatever the bit currently holds, replace it by the result of a fresh fair coin flip. Its permitted arrows are the same as those of KEEP-OR-FLIP, but each now carries probability \(1/2\).

For the path \(0\to1\to0\), the first step has probability \(1/2\), and the second has conditional probability \(1/2\) given the intermediate configuration. The path probability is therefore \(1/4\). The other path to zero, \(0\to0\to0\), also has probability \(1/4\). These are mutually exclusive histories, so their probabilities add:

\[P(c_2=0)=\tfrac14+\tfrac14=\tfrac12,\]

where \(c_2\) is the configuration after two steps. The probability of ending at one is also \(1/2\). Unlike the deterministic rule, COIN does not fix the outcome of a single run. Unlike the nondeterministic rule, it predicts the distribution of outcomes over independently repeated runs.

3.2

Sum and Product Rules

What is the result of a computation once states and transitions carry weights? It is the final state: a weight on each configuration at the last time. That weight answers the question each kind of rule asks about the end of a run. For a deterministic rule it is \(1\) at the configuration reached and \(0\) elsewhere. For a nondeterministic rule it is the number of runs that end at the configuration, and a nonzero number means the configuration is reachable. For a probabilistic rule it is the probability of ending there. The sum and product rules compute this weight from the weights of the transitions: the product rule gives the weight of a single path, and the sum rule combines the paths that end at the same configuration.

The three models differ in what they say about the future, but a run has the same structure in each: a sequence of transitions between configurations. This lets us separate two questions. What does a particular path contribute, and how do the paths to the same endpoint combine? We first assign weights to individual transitions, then use products along paths and sums across paths. The meaning of the weights will depend on the model; the calculation will have a common form.

3.2.1 The product rule along a path§

A path specifies every intermediate configuration, so following it requires every transition along it. Assign a weight \(w(i\to j)\) to each arrow. The weight of a two-step path is the product

\[w(i\to j\to k)=w(j\to k)\,w(i\to j).\]

For deterministic and nondeterministic rules, let an allowed arrow have weight one and a missing arrow weight zero. The product is one precisely when the whole path is permitted: a single missing transition makes it zero.

For a probabilistic rule, use the transition probabilities as weights. Multiplication then gives the probability of that particular history. The factors are conditional probabilities for successive steps; they need not describe independent events. Their dependence on the past is already accounted for by the current configuration.

For COIN, each two-step path has weight \((1/2)(1/2)=1/4\). A path of \(t\) steps has weight \(2^{-t}\). This determines the contribution of one history. An endpoint may be reached through several histories, whose contributions must still be combined.

3.2.2 The sum rule across paths§

An endpoint specifies where the run finishes without specifying how it got there. To calculate its weight, we therefore sum the contributions of all paths that reach it. For two steps from \(i\) to \(k\), the paths differ only in the intermediate configuration \(j\):

\[w(i\Rightarrow k)=\sum_j w(j\to k)\,w(i\to j).\]

The arrow \(\Rightarrow\) here denotes the complete two-step transition. Each term accounts for one route; the sum accounts for all routes to the chosen endpoint.

For a deterministic rule, only one path from the start is permitted. The sum is one at its endpoint and zero elsewhere. For a nondeterministic rule, the sum counts permitted paths. A positive count establishes reachability, but is not a probability.

For a probabilistic rule, the histories are mutually exclusive, so the sum is the endpoint probability. Distinguishing the two-step probability \(P_2\) from the one-step probabilities \(P\), we have

\[P_2(k\mid i)=\sum_jP(k\mid j)P(j\mid i).\]

For COIN, this is \(1/4+1/4=1/2\) at either endpoint. In all three models, every contribution is nonnegative. Adding a permitted path can therefore increase an endpoint’s total weight or leave it unchanged, but cannot reduce it. This restriction will matter when we encounter quantum transitions.

3.2.3 States and steps§

So far each calculation began from a definite state. The same rules apply to any state, with weight \(v_i\) on each configuration \(i\).

During a step, the contribution from \(i\) to \(j\) is \(w(i\to j)v_i\). Summing over all starting configurations gives the new weight at \(j\):

\[v^\prime_j=\sum_i w(i\to j)\,v_i.\]

The state thus collects the information needed to predict the next step, without retaining a separate list of all earlier paths. For COIN, \(v^\prime_0=v^\prime_1=(v_0+v_1)/2=1/2\). Every initial probability distribution becomes the same fair distribution.

Whether a step can be undone depends on what this update preserves. A reversible deterministic rule permutes the configurations; reversing its arrows restores every initial state. CNOT is an example on two bits, with arrows \(00\to00\), \(01\to01\), \(10\to11\), and \(11\to10\).

RESET and COIN instead send distinct initial states to the same final state. No rule acting only on that final state can recover which preparation was used. To undo such a process, we would need additional information outside this description.

3.3

Signed Weights

What changes if weights can be negative? We keep multiplying along paths and adding across paths. The new feature is cancellation: nonzero contributions can sum to zero. We first follow the signs through these rules, then construct a step in which cancellation restores the starting state. This prepares the extension to complex weights and their use in quantum transitions.

3.3.1 Negative weights§

So far, weights have counted paths or described probabilities. In either case they were nonnegative. Let us keep the same sum and product rules, but allow a state or an arrow to carry a negative real weight. This is a mathematical extension of our path description; its physical interpretation will come later.

The product rule still assigns a path the product of its arrow weights. For a path \(i\to j\to k\),

\[W(i\to j\to k)=w(i\to j)\,w(j\to k).\]

The sign now matters. A path with an odd number of negative arrow weights has negative weight; a path with an even number has positive weight. For example, \((1/2)(-1/2)=-1/4\), while \((-1/2)(-1/2)=1/4\). A negative arrow can therefore reverse the sign of a contribution that was already negative.

If the starting configuration itself has weight \(v_i\), its contribution along this path is \(v_iw(i\to j)w(j\to k)\). We include the sign of \(v_i\) as well as those of the arrows.

A negative path weight is not a negative probability or a negative number of paths. It is a signed contribution to a later sum. The path remains present in the diagram; what changes is how its contribution combines with others.

3.3.2 Cancellation across paths§

The sum rule still adds the contributions of all paths with the same start and endpoint. With two intermediate configurations,

\[W(i\to k)=w(i\to j_1)w(j_1\to k)+w(i\to j_2)w(j_2\to k).\]

Write the first pair of arrow weights as \(a,c\) and the second as \(b,d\). The two path contributions are \(ca\) and \(db\), and the total is \(ca+db\). If \(a=b=c=1/2\) and \(d=-1/2\), then

\[W(i\to k)=\frac14-\frac14=0.\]

Both paths have nonzero weight, yet their combined contribution vanishes. This is cancellation. With nonnegative weights, a sum can vanish only when every term vanishes. Signed weights allow a zero total even when individual terms are nonzero.

Cancellation need not be complete: \(1/4-1/8=1/8\). Contributions with the same sign reinforce one another: \(-1/4-1/4=-1/2\). Adding a path can now decrease the total weight, and removing a negative contribution can increase it. The sum of the weights is no longer required to be one or even positive.

Only contributions to the same final configuration are added. A weight \(+1/4\) at configuration \(0\) and a weight \(-1/4\) at configuration \(1\) remain two separate entries. Their sum is zero, but neither entry has vanished.

For state weights, the update therefore keeps exactly its earlier form:

\[v'_j=\sum_i v_iw(i\to j).\]

Multiplication carries each signed contribution forward; addition combines contributions at their common endpoint. These two rules now describe cancellation as well as accumulation. No rule for converting weights to observed probabilities has yet been specified.

3.3.3 The Hadamard step§

We can use cancellation to construct a step that spreads a definite input over two configurations, yet undoes itself when repeated. Call the step \(H\). Give three arrows weight \(c\) and the remaining arrow weight \(-c\):

\[w(0\to0)=w(0\to1)=w(1\to0)=c,\qquad w(1\to1)=-c.\]

Start at \(0\) with weight one. After one step the weights at \(0\) and \(1\) are \((c,c)\). After two steps, the paths \(0\to0\to0\) and \(0\to1\to0\) each contribute \(c^2\), giving \(2c^2\) at \(0\). The paths \(0\to0\to1\) and \(0\to1\to1\) contribute \(c^2\) and \(-c^2\), giving zero at \(1\).

To recover the original weight one, choose \(2c^2=1\), or \(c=1/\sqrt2\). This gives the Hadamard operation:

\[w(0\to0)=w(0\to1)=w(1\to0)=\tfrac1{\sqrt2},\qquad w(1\to1)=-\tfrac1{\sqrt2}.\]

The factor \(1/\sqrt2\) has been fixed by composition: two applications must return the original weights. Starting at \(1\) provides the other check. The paths to \(0\) cancel; the paths to \(1\) reinforce, including the path with two negative arrows, whose product is positive. Thus \(H^2=I\), where \(I\) is the identity step.

Notice what this choice does to the weights after one step. From either definite input, their squares add to one:

\[c^2+c^2=c^2+(-c)^2=1.\]

The weights themselves may be negative, and their sum need not be one. Their squares, however, are nonnegative and here give \(1/2\) for each configuration. This suggests using squared weights as probabilities, while retaining the signed weights for composition and cancellation. It is a motivation for the quantum probability rule, rather than a derivation of it; we state that rule when we connect these transitions to physical outcomes.

For general input weights \((v_0,v_1)\), the update is

\[(v'_0,v'_1)=\left(\frac{v_0+v_1}{\sqrt2},\frac{v_0-v_1}{\sqrt2}\right).\]

Applying the same update again gives \((v_0,v_1)\). The intermediate weights retain enough information to recover the input: starting at \(0\) gives \((1,1)/\sqrt2\), while starting at \(1\) gives \((1,-1)/\sqrt2\). Their signs determine which endpoint survives the second step.

If we replace the negative arrow by a positive one, the two contributions to each endpoint reinforce. Both inputs then produce the same intermediate weights, and the second step cannot recover the starting configuration. Cancellation is what makes the signed step reversible.

Negative real weights have given us opposite signs and cancellation. Next we extend weights to complex numbers, where a continuously varying phase takes the place of this two-way choice of sign, and connect the resulting rules to quantum transitions.

3.4

Complex Amplitudes and Interference

The signs of real amplitudes retain a distinction that probabilities discard. Complex amplitudes extend that distinction from a choice of sign to a continuously varying phase. We examine what this extension permits by constructing a square root of NOT, then ask how phase affects an observable outcome. Finally, we examine whether another part of the system keeps a record that distinguishes the contributing paths, changing which complete configurations the paths reach.

3.4.1 Complex weights§

Complex weights associated with states and transitions are called amplitudes. They obey the same sum and product rules as real weights.

The Hadamard operation satisfies \(H^2=I\). A square root of NOT is an operation \(S\) satisfying \(S^2=X\), where \(X\) denotes NOT. Neither deterministic reversible operation on one bit has this property: both the identity and NOT square to the identity.

Let \(S\) have stay-weight \(a\) and switch-weight \(b\), the same from either configuration. In two steps, staying twice or switching twice returns to the initial configuration, with total weight \(a^2+b^2\). Staying then switching or switching then staying reaches the opposite configuration, with total weight \(ab+ba=2ab\). For the combined operation to be NOT,

\[a^2+b^2=0,\qquad2ab=1.\]

For real \(a,b\), the first equation forces both to vanish, contradicting the second. Complex numbers permit cancellation between the squares themselves. With \(i^2=-1\), choose

\[a=\frac{1+i}{2},\qquad b=\frac{1-i}{2}.\]

Then \(a^2=i/2\), \(b^2=-i/2\), and \(2ab=1\). The two-step transformation is exactly NOT.

The weights of \(S\) now give the desired composition, but we still need to associate them with probabilities. In the real-weight example, squaring gave a nonnegative number. Here the squares \(a^2=i/2\) and \(b^2=-i/2\) cannot serve that purpose. Multiplying a complex weight by its conjugate offers a natural extension: if \(z=u+iv\), its conjugate is \(z^*=u-iv\), and

\[zz^*=(u+iv)(u-iv)=u^2+v^2=|z|^2.\]

This is the squared magnitude of \(z\). It is real and nonnegative, and becomes the ordinary square when the weight is real. We can therefore propose that a configuration with amplitude \(v_j\) has probability

\[p(j)=v_jv_j^*=|v_j|^2.\]

With this assignment, the requirement that probabilities sum to one becomes a condition on the amplitudes:

\[\sum_jp(j)=1\quad\Longleftrightarrow\quad\sum_j|v_j|^2=1.\]

We call this normalization. For the two outgoing weights of \(S\), \(|a|^2=|b|^2=1/2\), so their probabilities do sum to one. The same assignment also gives the probabilities \(1/2,1/2\) for a Hadamard step. Thus it agrees with the real-weight example and accommodates the complex weights just constructed.

A computation involves more than one step, however. The probability assignment must remain consistent as weights multiply along paths and add at their endpoints. Multiplication has a useful property here:

\[|z_1z_2|^2=(z_1z_2)(z_1z_2)^*=|z_1|^2|z_2|^2.\]

The squared magnitude of a path product is the product of the squared magnitudes of its factors. When several paths meet, their amplitudes must still be added before assigning a probability. For two contributions,

\[|A+B|^2=|A|^2+|B|^2+AB^*+A^*B.\]

The last two terms retain the dependence on how the contributions combine. In two steps of \(S\), the return contributions are \(A=i/2\) and \(B=-i/2\); their sum is zero, and so is the return probability. Assigning separate probabilities and adding them would give \(1/4+1/4=1/2\), losing the cancellation. The distinction is therefore between adding amplitudes at a common endpoint and adding probabilities over distinct final configurations.

This cancellation changes the probability of a particular configuration. The total over all final configurations must nevertheless remain one. That places a restriction on the transition weights. If the input amplitudes are \(v_i\), the sum and product rules give

\[v'_j=\sum_i v_iw(i\to j).\]

For a definite input \(i\), only \(v_i=1\) is nonzero, so the outgoing amplitudes are simply \(w(i\to j)\). Normalization then requires

\[\sum_j|w(i\to j)|^2=1\]

for each input configuration. This checks the transition on definite inputs. With several nonzero input amplitudes, contributions from different starting configurations combine at each endpoint, producing the same kind of cross terms as \(A+B\) above. Summing over endpoints gives

\[\sum_j|v'_j|^2=\sum_i|v_i|^2\sum_j|w(i\to j)|^2+\sum_{i\ne k}v_i^*v_k\sum_jw(i\to j)^*w(k\to j).\]

The outgoing normalization condition makes the first term equal to the original total \(\sum_i|v_i|^2\). The second term must therefore vanish for every choice of input amplitudes. Since their relative magnitudes and complex directions can vary, this requires

\[\sum_jw(i\to j)^*w(k\to j)=0\qquad(i\ne k).\]

This cross-sum condition allows contributions to reinforce or cancel at individual endpoints while ensuring that their cross terms cancel in the total. Together with outgoing normalization, it makes the proposed probability assignment compatible with the amplitude update. Each step takes a normalized input to a normalized output, so a sequence of such steps preserves total probability.

The step \(S\) satisfies both requirements. Its outgoing squared magnitudes sum to \(|a|^2+|b|^2=1\), and the cross sum for its two inputs is

\[a^*b+b^*a=-\frac i2+\frac i2=0.\]

It therefore preserves normalization for arbitrary input amplitudes, as well as for the definite inputs used in its construction. After two steps, the return amplitude \(a^2+b^2=0\) gives probability zero, and the switch amplitude \(2ab=1\) gives probability one. Both the one-step probabilities and the composition into NOT fit the proposed rule.

The complex directions appearing in these sums can be expressed by writing a nonzero amplitude as \(z=re^{i\phi}\). Here \(r=|z|\) is its magnitude and \(\phi\) its phase. The probability \(|z|^2=r^2\) retains the magnitude but discards the phase. Positive and negative real weights correspond to phases zero and \(\pi\); complex weights allow the intervening angles. Multiplication adds phases, and addition depends on their relative values. This is how two amplitude lists with the same probabilities can give different probabilities after a further transition.

3.4.2 Interference and phase§

When paths end at the same configuration, we add their amplitudes and then take the squared magnitude. The probability rule therefore gives

\[p(k)=\Bigl|\sum_{\text{paths to }k}\text{path amplitude}\Bigr|^2.\]

The contributions can reinforce or cancel. For two Hadamard steps starting at \(0\), the two paths to \(0\) each contribute \(1/2\). They add to one, giving probability one. The two paths to \(1\) contribute \(1/2\) and \(-1/2\). They cancel, giving probability zero.

Taking the squared magnitude of each path separately would give \(1/4+1/4=1/2\) at either endpoint. Adding the amplitudes first raises one probability and lowers the other. This effect is called interference. It is constructive when the probability is greater than the sum of the separate squared magnitudes, and destructive when it is smaller. Paths whose amplitudes combine in this way are called coherent.

For complex amplitudes, phase determines how the contributions combine. Multiplying every amplitude by the same factor \(e^{i\theta}\) changes all their phases by the same amount. Every later sum acquires that same factor, and its squared magnitude stays unchanged because \(|e^{i\theta}|=1\). Such a common phase is called a global phase. It has no effect on the probabilities, even after further transitions.

The phase difference between two amplitudes is their relative phase. Changing it can change their sum. For example, take the state amplitudes

\[(v_0,v_1)=\left(\frac1{\sqrt2},\frac{e^{i\phi}}{\sqrt2}\right).\]

Both squared magnitudes are \(1/2\), whatever the value of \(\phi\). But the two contributions arriving at \(0\) after a Hadamard step are \(1/2\) and \(e^{i\phi}/2\). Their sum depends on \(\phi\), so

\[p(0)=\left|\frac{1+e^{i\phi}}2\right|^2=\frac{1+\cos\phi}{2}.\]

At \(\phi=0\), the contributions have the same sign and add to one. At \(\phi=\pi\), they have opposite signs and cancel. At \(\phi=\pi/2\), the probability is \(1/2\). The initial probabilities are the same in all three cases; the relative phase changes the probabilities after \(H\).

A simple way to change this phase is to multiply the amplitude at \(1\) by \(-1\), leaving the amplitude at \(0\) unchanged. This is the operation \(Z\), with stay-weights \(Z(0\to0)=1\) and \(Z(1\to1)=-1\). It changes the relative phase by \(\pi\). Starting at \(0\), two Hadamard steps return to \(0\); inserting \(Z\) between them gives \(1\) instead. An algorithm can use such phase changes to control which contributions reinforce and which cancel, and so change the final probabilities.

3.4.3 Path information§

Two Hadamard steps starting at \(0\) return to \(0\). The two contributions to final configuration \(1\) are \(+1/2\) and \(-1/2\), so they cancel. What changes if another part of the machine records which intermediate configuration was visited?

Introduce a second bit as a record, initially zero. A complete configuration now has two labels, \(ij\): \(i\) is the value of the first system and \(j\) the record. Thus \(10\) and \(11\) are different configurations even though their first labels agree. We apply the same path rules to these complete configurations: multiply weights along a path, add amplitudes at a common endpoint, and then take the squared magnitude.

Starting at \(00\), apply \(H\) to the first label while leaving the record unchanged. This gives configurations \(00\) and \(10\), each with amplitude \(1/\sqrt2\). Next record the first label by a controlled-NOT operation: leave the second label alone when the first is zero, and flip it when the first is one. Its transitions are

\[00\to00,\quad01\to01,\quad10\to11,\quad11\to10,\]

each with weight one. The two occupied configurations are now \(00\) and \(11\), still with amplitudes \(1/\sqrt2\). Apply the final \(H\) to the first label only. From \(00\), it reaches \(00\) and \(10\), with transition weights \(+1/\sqrt2\) each. From \(11\), it reaches \(01\) with weight \(+1/\sqrt2\) and \(11\) with weight \(-1/\sqrt2\).

The final amplitudes, in the order \(00,01,10,11\), are

\[\left(\frac12,\frac12,\frac12,-\frac12\right).\]

The contributions \(+1/2\) and \(-1/2\) associated with first-label value one end at \(10\) and \(11\). They cannot cancel because these are different complete configurations. Each has probability \(1/4\). If we ask only whether the first label is one, we include both distinct outcomes and add their probabilities:

\[p(\text{first label}=1)=p(10)+p(11)=\frac14+\frac14=\frac12.\]

Ignoring the record does not make its two values the same configuration. The loss of interference here follows from the different endpoints, whether or not anyone reads the record.

We can recover the earlier interference by undoing the recording step before the final \(H\). Controlled-NOT is its own inverse: a second application takes \(00\) back to \(00\) and \(11\) back to \(10\), both with weight one. The record is again zero on both alternatives, and their amplitudes remain \(1/\sqrt2\). Now the final \(H\) has two routes to the same endpoint \(10\), with contributions \(+1/2\) and \(-1/2\). They cancel. The contributions to \(00\) add to one, restoring a certain return to \(00\).

This is uncomputation applied to path information. It means reversing the operation that created the record while preserving the amplitudes, not merely deleting a label from our description. The bookkeeping lesson is that every part of the machine capable of distinguishing the paths belongs in the configuration. Chapter 4 introduces state notation for these amplitude lists and states the physical rules for evolution, measurement, and composite systems.
