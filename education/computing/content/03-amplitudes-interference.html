3.1

States and Transitions

Deterministic, nondeterministic, and probabilistic computations look different. To compare them, we first describe what we know about a register at a given time, its state, and find that all three kinds of knowledge take the same form. We then ask the same question under each kind of rule: from a given start, where can a two-step run end? Doing the calculation three times shows what the three kinds of rule have in common.

3.1.1 States§

Take a register holding one bit. Its possible contents, \(0\) and \(1\), are its configurations. At any moment the register holds exactly one of them.

Do we always know which? We may have set the bit ourselves, and then we know it. We may know only that either configuration is possible. Or the bit may have been set by a fair coin, so that each configuration has probability \(1/2\). What we know about the register at a given time is its state.

All three kinds of knowledge take the same form: a number \(v_j\) for each configuration \(j\), its weight in the state.

What we know\(v_0\)\(v_1\)
The bit is \(0\)\(1\)\(0\)
Either value is possible\(1\)\(1\)
A fair coin set the bit\(1/2\)\(1/2\)

The weights mean different things in different rows. A weight \(1\) or \(0\) records whether a configuration is possible; a probability records how often it occurs. A state with weight \(1\) on one configuration and \(0\) on the others is definite, and we name it by that configuration.

3.1.2 Transitions§

A computation changes the register step by step. A transition rule says which configurations may follow each one. As an example, take NOT, which flips the bit.

We draw a rule as a state diagram: a circle for each configuration, and an arrow \(i\to j\) whenever the rule lets \(j\) follow \(i\). Each arrow carries a weight. For NOT every weight is \(1\), because the step certainly follows the arrow.

Applying a rule step by step produces a run \(c_0,c_1,c_2\), where \(c_t\) is the configuration after \(t\) steps. From \(0\), NOT gives \(0,1,0\). To see a run in a diagram, copy the configurations once for each time \(t=0,1,2\) and join the copies by the arrows of the rule. In this time-expanded diagram, a run is a path from time \(0\) to time \(2\).

Rules differ in how many arrows leave each configuration and in what their weights mean. These two differences separate the three kinds of rule that follow.

3.1.3 Deterministic transitions§

Compare NOT with RESET, which writes \(0\) whatever the bit holds.

ConfigurationNext under NOTNext under RESET
\(0\)\(1\)\(0\)
\(1\)\(0\)\(0\)

From \(0\), NOT gives the run \(0,1,0\) and RESET gives \(0,0,0\). Under both rules, exactly one arrow leaves each configuration, so the start fixes the whole run: both rules are deterministic. From a definite state, the state stays definite at every step.

Can a run also be traced backward? Under NOT, exactly one arrow enters each configuration, so the previous bit is always known. Under RESET, two arrows enter \(0\), and a run that reaches \(0\) may have come from either bit. A deterministic rule with exactly one arrow entering each configuration is reversible.

3.1.4 Nondeterministic transitions§

Nondeterminism relaxes the requirement of a unique successor. A configuration may have several permitted successors, so specifying the present no longer specifies a unique future. The rule describes a set of possible runs rather than a single run.

For a bit, consider KEEP-OR-FLIP: from either configuration, both \(0\) and \(1\) are permitted. Its state diagram has all four arrows. Starting from \(0\), two steps admit four paths:

\[0\to0\to0,\qquad0\to1\to0,\qquad0\to0\to1,\qquad0\to1\to1.\]

A path is possible when every transition along it is permitted. A configuration is reachable when at least one possible path ends there. Both zero and one are therefore reachable after two steps. In a nondeterministic model of computation, acceptance is defined in the same way: an input is accepted if at least one permitted run accepts it.

This is a statement about possibility, not a mechanism for choosing among paths. Even if more paths reached one endpoint than another, the rule would not make that endpoint more likely. Counting possibilities and assigning probabilities are different tasks. To predict how often a future occurs, we need more information on the arrows.

3.1.5 Probabilistic transitions§

A probabilistic rule supplies the information that nondeterminism leaves unspecified: the probability of each next configuration, given the present one. We write the probability on an arrow \(i\to j\) as \(P(j\mid i)\), read “the probability of \(j\) given \(i\).” Since some next configuration must occur, the probabilities leaving each configuration add to one.

The current configuration is assumed to contain all the information needed for this prediction. If earlier history matters, that history must be included in the configuration. With this assumption, the process is called Markov.

Consider COIN: whatever the bit currently holds, replace it by the result of a fresh fair coin flip. Its permitted arrows are the same as those of KEEP-OR-FLIP, but each now carries probability \(1/2\).

For the path \(0\to1\to0\), the first step has probability \(1/2\), and the second has conditional probability \(1/2\) given the intermediate configuration. The path probability is therefore \(1/4\). The other path to zero, \(0\to0\to0\), also has probability \(1/4\). These are mutually exclusive histories, so their probabilities add:

\[P(c_2=0)=\tfrac14+\tfrac14=\tfrac12,\]

where \(c_2\) is the configuration after two steps. The probability of ending at one is also \(1/2\). Unlike the deterministic rule, COIN does not fix the outcome of a single run. Unlike the nondeterministic rule, it predicts the distribution of outcomes over independently repeated runs.

3.2

Sum and Product Rules

What is the result of a computation once states and transitions carry weights? It is the final state: a weight on each configuration at the last time. That weight answers the question each kind of rule asks about the end of a run. For a deterministic rule it is \(1\) at the configuration reached and \(0\) elsewhere. For a nondeterministic rule it is the number of runs that end at the configuration, and a nonzero number means the configuration is reachable. For a probabilistic rule it is the probability of ending there. The sum and product rules compute this weight from the weights of the transitions: the product rule gives the weight of a single path, and the sum rule combines the paths that end at the same configuration.

The three models differ in what they say about the future, but a run has the same structure in each: a sequence of transitions between configurations. This lets us separate two questions. What does a particular path contribute, and how do the paths to the same endpoint combine? We first assign weights to individual transitions, then use products along paths and sums across paths. The meaning of the weights will depend on the model; the calculation will have a common form.

3.2.1 The product rule along a path§

A path specifies every intermediate configuration, so following it requires every transition along it. Assign a weight \(w(i\to j)\) to each arrow. The weight of a two-step path is the product

\[w(i\to j\to k)=w(j\to k)\,w(i\to j).\]

For deterministic and nondeterministic rules, let an allowed arrow have weight one and a missing arrow weight zero. The product is one precisely when the whole path is permitted: a single missing transition makes it zero.

For a probabilistic rule, use the transition probabilities as weights. Multiplication then gives the probability of that particular history. The factors are conditional probabilities for successive steps; they need not describe independent events. Their dependence on the past is already accounted for by the current configuration.

For COIN, each two-step path has weight \((1/2)(1/2)=1/4\). A path of \(t\) steps has weight \(2^{-t}\). This determines the contribution of one history. An endpoint may be reached through several histories, whose contributions must still be combined.

3.2.2 The sum rule across paths§

An endpoint specifies where the run finishes without specifying how it got there. To calculate its weight, we therefore sum the contributions of all paths that reach it. For two steps from \(i\) to \(k\), the paths differ only in the intermediate configuration \(j\):

\[w(i\Rightarrow k)=\sum_j w(j\to k)\,w(i\to j).\]

The arrow \(\Rightarrow\) here denotes the complete two-step transition. Each term accounts for one route; the sum accounts for all routes to the chosen endpoint.

For a deterministic rule, only one path from the start is permitted. The sum is one at its endpoint and zero elsewhere. For a nondeterministic rule, the sum counts permitted paths. A positive count establishes reachability, but is not a probability.

For a probabilistic rule, the histories are mutually exclusive, so the sum is the endpoint probability. Distinguishing the two-step probability \(P_2\) from the one-step probabilities \(P\), we have

\[P_2(k\mid i)=\sum_jP(k\mid j)P(j\mid i).\]

For COIN, this is \(1/4+1/4=1/2\) at either endpoint. In all three models, every contribution is nonnegative. Adding a permitted path can therefore increase an endpoint’s total weight or leave it unchanged, but cannot reduce it. This restriction will matter when we encounter quantum transitions.

3.2.3 States and steps§

So far each calculation began from a definite state. The same rules apply to any state, with weight \(v_i\) on each configuration \(i\).

During a step, the contribution from \(i\) to \(j\) is \(w(i\to j)v_i\). Summing over all starting configurations gives the new weight at \(j\):

\[v^\prime_j=\sum_i w(i\to j)\,v_i.\]

The state thus collects the information needed to predict the next step, without retaining a separate list of all earlier paths. For COIN, \(v^\prime_0=v^\prime_1=(v_0+v_1)/2=1/2\). Every initial probability distribution becomes the same fair distribution.

Whether a step can be undone depends on what this update preserves. A reversible deterministic rule permutes the configurations; reversing its arrows restores every initial state. CNOT is an example on two bits, with arrows \(00\to00\), \(01\to01\), \(10\to11\), and \(11\to10\).

RESET and COIN instead send distinct initial states to the same final state. No rule acting only on that final state can recover which preparation was used. To undo such a process, we would need additional information outside this description.

3.3

Signed Weights

In all three kinds of rule, a weight counts runs or gives a probability, so no weight is negative. Is every physical step of this kind? We take a bit carried by a single atom, describe an experiment on it, and show that no rule with nonnegative weights reproduces the experiment. Weights must be allowed to be negative. A negative weight is not a probability, so the final state no longer tells us directly what a measurement will show, and we need a rule that turns weights into probabilities. That rule limits which transitions are allowed, and with these limits the observations fix the weights of the operation in the experiment.

3.3.1 An operation that probability cannot describe§

The bits in a computer are held by devices made of very many atoms. Let a single atom carry the bit instead, with two of its energy levels as the configurations \(0\) and \(1\). A bit of this kind is a qubit. Looking at the atom, a measurement, reports one of the two configurations.

A suitable pulse of light carries out an operation on the atom, which we call \(H\). Experiments show three things:

  1. Apply \(H\) once, starting from either configuration, and measure: \(0\) and \(1\) are equally likely.
  2. Apply \(H\) twice without measuring in between: the measurement returns the starting configuration with certainty.
  3. Measure between the two applications: the final outcomes are again equally likely.

Can a rule of the kind we know describe \(H\)? A probabilistic rule that satisfies observation 1 gives each next configuration probability \(1/2\), so it is COIN. But for COIN, two steps from \(0\) end at \(1\) with probability \(1/4+1/4=1/2\), while observation 2 requires \(0\).

Could other nonnegative weights succeed? Two steps from \(0\) reach \(1\) along two paths, through \(0\) and through \(1\). By the product and sum rules, the final weight at \(1\) is

\[w(0\to0)\,w(0\to1)+w(0\to1)\,w(1\to1).\]

By observation 1, both configurations can follow either configuration, so all four weights are nonzero. If they are also nonnegative, both terms are positive and their sum is not \(0\).

Proposition. No rule with nonnegative weights on the configurations \(0\) and \(1\) reproduces observations 1 and 2.

What would? If one of the two paths has a negative weight, the two contributions can cancel, and the final weight at \(1\) can be \(0\) although both paths are present. A rule with further configurations, hidden from the measurement, is not excluded by this argument. Quantum mechanics takes the other route: it keeps the two configurations and lets the weights be negative. Weights that may be negative are called amplitudes.

3.3.2 From weights to probabilities§

A negative weight is not a probability. Yet a measurement still reports a single configuration, so the final state must determine the probability of each outcome. Which rule does this?

First some notation. We write a state of a qubit as \(v_0\ket0+v_1\ket1\), where \(\ket0\), read “ket zero,” stands for the definite state \(0\), and \(v_0\) and \(v_1\) are the weights. A state with both weights nonzero is a superposition.

Assumption. The probability of outcome \(j\) depends only on the magnitude of its weight, as \(|v_j|^p\) for some fixed power \(p\gt0\).

The probabilities add to \(1\), so every state satisfies \(\sum_j|v_j|^p=1\), and every step must keep this sum equal to \(1\). A step acts by the product and sum rules, \(v^\prime_j=\sum_iw(i\to j)\,v_i\). For which \(p\) can such a step turn a definite state into a superposition, as \(H\) must? A theorem of Banach and Lamperti answers this. When \(p\neq2\), the only steps that keep \(\sum_j|v_j|^p\) fixed for every state send each configuration to a single configuration, possibly changing the sign of its weight. Such a step never creates a superposition, so it cannot be \(H\). Therefore \(p=2\).

Measurement rule. Measuring the state \(v_0\ket0+v_1\ket1\) gives outcome \(j\) with probability \(v_j^2\).

Which steps keep \(\sum_jv_j^2=1\)? Start from the definite state \(i\). After one step its weights are \(w(i\to j)\), so

\[\sum_jw(i\to j)^2=1:\]

the squared weights leaving each configuration add to \(1\). This is the normalization condition. Now start from weight \(1/\sqrt2\) on each of two configurations \(i\neq k\). After one step, the sum of squared weights is

\[\frac12\sum_j\bigl(w(i\to j)+w(k\to j)\bigr)^2=1+\sum_jw(i\to j)\,w(k\to j).\]

It equals \(1\) only if

\[\sum_jw(i\to j)\,w(k\to j)=0,\]

the cross-sum condition. Expanding \(\sum_jv_j^{\prime2}\) for a general state shows that the two conditions together keep the sum of squares equal to \(1\) for every state.

NOT satisfies both conditions. RESET satisfies the normalization condition but not the cross-sum condition, since \(w(0\to0)\,w(1\to0)=1\). Applied to weights \(1/\sqrt2\) and \(-1/\sqrt2\), its two contributions at \(0\) cancel and nothing is left. RESET is therefore not an operation on a qubit alone.

3.3.3 The Hadamard step§

We can now find the weights of \(H\) from the observations. By observation 1, one step from either configuration gives each outcome with probability \(1/2\). By the measurement rule, every weight of \(H\) has square \(1/2\), so each weight is \(1/\sqrt2\) or \(-1/\sqrt2\). Which signs?

By observation 2, two steps from \(0\) end at \(1\) with weight \(0\):

\[w(0\to0)\,w(0\to1)+w(0\to1)\,w(1\to1)=w(0\to1)\bigl(w(0\to0)+w(1\to1)\bigr)=0.\]

Since \(w(0\to1)\neq0\), the weights of the two arrows that stay put are opposite: \(w(1\to1)=-w(0\to0)\). The cross-sum condition then gives \(w(0\to0)\bigl(w(1\to0)-w(0\to1)\bigr)=0\), so the two arrows that switch carry equal weights. Choosing both remaining signs positive gives the Hadamard operation:

\[w(0\to0)=w(0\to1)=w(1\to0)=\tfrac1{\sqrt2},\qquad w(1\to1)=-\tfrac1{\sqrt2}.\]

Check observation 2 from \(0\). The two paths to \(0\) have weights \(\tfrac12\) and \(\tfrac12\), which add to \(1\). The two paths to \(1\) have weights \(\tfrac12\) and \(-\tfrac12\), which cancel. Observation 3 also follows: a measurement after one step leaves a definite state, and one more step from it gives each outcome with probability \(1/2\).

In ket notation, one step turns \(\ket0\) into \((\ket0+\ket1)/\sqrt2\) and \(\ket1\) into \((\ket0-\ket1)/\sqrt2\). The two states give the same probabilities when measured; they differ only in the sign of one weight. That sign is what the second step reads, and it is why the starting configuration returns.

3.4

Complex Amplitudes and Interference

The signs of real amplitudes retain a distinction that probabilities discard. Complex amplitudes extend that distinction from a choice of sign to a continuously varying phase. We examine what this extension permits by constructing a square root of NOT, then ask how phase affects an observable outcome. Finally, we consider a further condition on interference: whether another part of the system keeps a record that distinguishes the contributing paths.

3.4.1 Complex weights§

The Hadamard operation returns a bit to its starting state after two steps. We can ask for a different composition: two identical steps whose combined action is NOT. Writing NOT as \(X\), we seek \(S\) such that \(S^2=X\). No reversible deterministic rule on one bit does this: both the identity and NOT square to the identity.

To construct such a step with amplitudes, let its stay-weight be \(a\) and its switch-weight be \(b\), the same from either configuration. Two steps return to the start by staying twice or switching twice, and reach the opposite configuration by staying then switching or switching then staying. The required path sums are therefore

\[a^2+b^2=0,\qquad2ab=1.\]

For real \(a,b\), the first equation forces both to vanish, contradicting the second. Complex numbers permit cancellation between the squares themselves. With \(i^2=-1\), choose

\[a=\frac{1+i}{2},\qquad b=\frac{1-i}{2}.\]

Then \(a^2=i/2\), \(b^2=-i/2\), and \(2ab=1\). The two-step transformation is exactly NOT. This construction shows what the larger number system permits; it is not a derivation of the quantum postulates.

The probability rule must also extend to complex amplitudes. For \(z=u+iv\), define its conjugate \(z^*=u-iv\) and its squared magnitude \(|z|^2=z^*z=u^2+v^2\). Quantum probabilities are squared magnitudes, which are real and nonnegative, rather than complex squares.

Our proposed step has \(|a|^2+|b|^2=1\) and \(a^*b+b^*a=0\). These are the complex versions of the normalization and cross-sum conditions. They ensure that the step preserves total probability for every input state. Its inverse is obtained by reversing the arrows and conjugating their weights.

A nonzero complex amplitude can also be written \(z=re^{i\phi}\), with magnitude \(r\) and phase \(\phi\). Positive and negative real amplitudes have phases zero and \(\pi\); complex amplitudes allow the angles between them. Multiplication multiplies magnitudes and adds phases. We still multiply along paths and add across paths, but now take the squared magnitude of the total to obtain an outcome probability.

3.4.2 Interference and phase§

The probability of an outcome depends on the total amplitude reaching it, not on separate probabilities assigned to its contributing paths. This is interference:

\[p(k)=\Bigl|\sum_{\text{paths to }k}\text{path amplitude}\Bigr|^2.\]

Contributions interfere constructively when their combination raises the probability above the sum of their individual squared magnitudes, and destructively when it lowers it. For two Hadamard steps from zero, the two contributions to one are \(+1/2\) and \(-1/2\). Adding first gives zero probability; squaring first would give \(1/4+1/4=1/2\), the incorrect COIN prediction.

In the unmeasured experiment, the intermediate configurations label terms in an amplitude calculation. They are not separately observed events to which we assign classical path probabilities. The alternatives are coherent: their amplitudes combine before the probability is calculated. Measuring the intermediate configuration changes the experiment, as observation 3 showed.

The effect of phase follows directly. Multiplying every amplitude by the same \(e^{i\theta}\) multiplies every later amplitude by that factor. Since its magnitude is one, all outcome probabilities remain unchanged. This is a global phase; vectors differing only by it describe the same physical state.

A relative phase changes one contribution with respect to another, so it can change their sum. Consider

\[\frac1{\sqrt2}\bigl(\ket0+e^{i\phi}\ket1\bigr).\]

A direct computational-basis measurement gives zero and one with probability \(1/2\), independently of \(\phi\). After \(H\), however, the contributions to zero are \(1/2\) and \(e^{i\phi}/2\). Consequently,

\[p(0)=\left|\frac{1+e^{i\phi}}2\right|^2=\frac{1+\cos\phi}{2}.\]

At \(\phi=0\), zero is certain; at \(\phi=\pi\), it is impossible. Intermediate phases give intermediate probabilities. The phase that the first measurement could not reveal therefore controls the result of a later one.

The operation \(Z\), with stay-weights \(Z(0\to0)=1\) and \(Z(1\to1)=-1\), changes this relative phase by \(\pi\). Inserting it between two Hadamard steps changes the output from \(\ket0\) to \(\ket1\). This is a mechanism a quantum algorithm can use: encode information in relative phases, then combine amplitudes so that the information affects measurable probabilities.

3.4.3 Path information and interference§

Interference requires the contributions to end at the same configuration. If another register distinguishes them, the configuration of the whole system is no longer the same, even when the qubit we intend to measure has the same value. This explains why a record can remove interference without anyone reading it.

Let a second bit start at zero and record the intermediate value of the first. Write the first qubit’s label before the record’s label. Insert CNOT between two applications of \(H\), using the first qubit as control and the record as target. Each \(H\) acts only on the first qubit:

\[\ket{00}\xrightarrow{H}\tfrac1{\sqrt2}\bigl(\ket{00}+\ket{10}\bigr)\xrightarrow{\text{CNOT}}\tfrac1{\sqrt2}\bigl(\ket{00}+\ket{11}\bigr)\xrightarrow{H}\tfrac12\bigl(\ket{00}+\ket{10}+\ket{01}-\ket{11}\bigr).\]

The amplitudes contributing to first-qubit outcome one are still \(+1/2\) and \(-1/2\). They now belong to different joint configurations, \(10\) and \(11\). They cannot cancel. Ignoring the record means adding the probabilities of these distinguishable joint outcomes, giving \(1/4+1/4=1/2\) for the first qubit.

The relevant change is the existence of a distinguishable record, not a reader’s knowledge of it. To restore the original interference, apply CNOT a second time before the final \(H\). This returns the record to zero on both alternatives. The state becomes \((\ket{00}+\ket{10})/\sqrt2\), and the final \(H\) gives \(\ket{00}\). Here uncomputation restores the common endpoint needed for cancellation.

Identical records preserve interference; perfectly distinguishable records remove it; partial distinguishability gives an intermediate result. For a quantum computation, tracking only the intended output is therefore insufficient. We must also track any workspace that distinguishes alternatives we want to interfere, and coherently return those records to a common state when needed. The next chapters provide the vector and composite-system descriptions needed to follow these dependencies systematically.
