5.1

Quantum Model of Computation

The postulates tell us what a system can be and how it changes, but not how to make it answer a question. A procedure must decide where to start, which steps to take, and what to read at the end. We set up these three stages first, then see how a sequence of steps combines into one evolution, and finally ask what a run returns and what it costs.

5.1.1 Input, evolution, and output§

How do states, unitary steps, and measurement become a computation? Start from a task: an input is given, and some output would count as a correct answer. The postulates give us three things to choose.

We choose an initial state \(\ket{\psi_{\mathrm{in}}}\) that encodes the input. We choose unitary steps, which together form one unitary \(U\). And we choose a measurement, which returns a classical result \(y\):

\[\ket{\psi_{\mathrm{out}}}=U\ket{\psi_{\mathrm{in}}}\quad\xrightarrow{\ \text{measure}\ }\quad y.\]

Can we read \(\ket{\psi_{\mathrm{out}}}\) itself? No. A measurement returns one label per run, with probability equal to the squared magnitude of its amplitude. The output state fixes how likely each answer is; a run delivers one of them. So a computation works only if it makes the correct answer likely.

Is \(U\) one step? Not necessarily. Naming the whole evolution says nothing about how a machine carries it out or how long that takes. Building \(U\) from available operations, and counting the cost, is part of the algorithm.

A procedure may also measure partway through and choose later steps from the recorded result. We start with the simplest arrangement: one measurement, at the end.

5.1.2 Composition and interference§

If \(U\) is built from several steps, how do they combine? Call an operation that a machine applies directly a gate. A program is an ordered list of gates.

We already know how two steps combine: amplitudes multiply along paths and add over the intermediate configurations, which is the matrix product, with the later step on the left. For gates \(U_1,\dots,U_T\) applied in that order,

\[U=U_T\cdots U_2U_1.\]

Each gate preserves the length of every state, so the product does too, and the outcome probabilities still sum to one. The number \(T\) counts the gates; writing their product as one symbol does not remove their cost.

Why use a sequence at all, if the result is one unitary? Because what happens in the middle can decide the answer without showing up in the middle. Can a step that changes no probability matter? Compare two programs that start from \(\ket0\): \(H\) then \(H\), and \(H\), \(Z\), \(H\). After the first \(H\), each outcome has probability \(1/2\), and \(Z\) only changes the sign of the amplitude at \(1\), so those probabilities stay \(1/2\). Multiplying the matrices,

\[HH=I,\qquad HZH=\frac12\begin{pmatrix}1&1\\1&-1\end{pmatrix}\begin{pmatrix}1&0\\0&-1\end{pmatrix}\begin{pmatrix}1&1\\1&-1\end{pmatrix}=\begin{pmatrix}0&1\\1&0\end{pmatrix}=X.\]

The first program returns \(\ket0\); the second returns \(\ket1\). The sign that \(Z\) changed was invisible to a measurement in the middle, yet the last \(H\) turned it into the opposite answer. An intermediate state is not an answer: its relative phases decide how later steps combine its paths.

5.1.3 Readout and computational cost§

What does one run return, and what must we count to say what a computation costs? For a final measurement in the computational basis, result \(y\) has probability

\[p(y)=|\braket y{\psi_{\mathrm{out}}}|^2=|\bra yU\ket{\psi_{\mathrm{in}}}|^2.\]

Suppose the correct answer has probability \(3/4\). One run is then wrong a quarter of the time. Repeating the whole computation and taking the most frequent answer makes an error less likely, but each repetition needs a freshly prepared input and costs the full work again. An algorithm whose success is probabilistic must state its success probability for the inputs it promises to handle.

What may the input depend on? A procedure must say what information about the task it is given. It cannot assume the answer is already encoded in the input for free.

So what does a computation cost? We count what a machine must actually do: the qubits it uses, the gates it applies, the number of successive gate layers, the repetitions, and the work to prepare the input and interpret the output. The program \(H,Z,H\) and the single gate \(X\) compute the same NOT; one uses three gates and the other one.

Does a one-qubit computation show that quantum computers can be faster? No. A speedup is a claim about tasks of growing size, comparing costs under the same rules for accessing the input.

5.2

Single-Qubit Computation

The model is general. Can one qubit already carry out a complete computation, from input to answer? To follow one, we first need a way to write a program down. With it, we run a program whose answer is decided by a relative sign, and then let that sign vary continuously to see how the answer depends on it.

5.2.1 A single-qubit circuit§

How should we write a program so that the order of its steps and its final measurement are visible at a glance? Start with the simplest register, one qubit, in the state \(\ket{\psi_{\mathrm{in}}}=a\ket0+b\ket1\) with \(|a|^2+|b|^2=1\). For a definite input bit \(x\), we prepare \(\ket x\): initialize the qubit to \(\ket0\), and apply \(X\) if the input is one.

We draw the program as a circuit, read from left to right. A horizontal line, the wire, follows the qubit through time, with its initial state written at the left. A box labelled H, X, or Z applies that gate; a bare stretch of wire leaves the state unchanged. The wire records the order of operations, not a path through space.

A box labelled M is a computational-basis measurement. After it, a double line carries the classical result. The two kinds of line carry different things: before M, the wire carries a state with amplitudes; after it, the double line carries one bit.

In the example below, H sends \(\ket0\) to \((\ket0+\ket1)/\sqrt2\), and the measurement returns either bit with probability \(1/2\). A box may also stand for a composite operation built from many gates. Its size on the page says nothing about its cost.

5.2.2 A complete one-qubit computation§

Can interference compute something? Take the simplest task with a definite answer: reverse an input bit, so that zero gives one and one gives zero. \(X\) does this in one step. Let us do it instead with \(H\), then \(Z\), then \(H\), and follow the amplitudes. For input zero,

\[\ket0\xrightarrow{H}\frac{\ket0+\ket1}{\sqrt2}\xrightarrow{Z}\frac{\ket0-\ket1}{\sqrt2}\xrightarrow{H}\ket1.\]

After the first H, both outcomes would have probability \(1/2\). Z changes their relative sign without changing those probabilities. The final H sends two paths to each endpoint. At zero the contributions are \(1/2\) and \(-1/2\), and they cancel; at one they are both \(1/2\), and they add to one. The measurement returns one with certainty.

Does the program also work on the other input? Starting from one,

\[\ket1\xrightarrow{H}\frac{\ket0-\ket1}{\sqrt2}\xrightarrow{Z}\frac{\ket0+\ket1}{\sqrt2}\xrightarrow{H}\ket0.\]

So the circuit computes NOT on both inputs. By linearity it sends \(a\ket0+b\ket1\) to \(b\ket0+a\ket1\), which is what \(HZH=X\) says. It spends three gates on what one gate does; its purpose is to show interference computing the answer.

Which parts are essential? Without Z, the two H gates cancel and the input comes back unchanged. With a measurement after the first H, the state becomes \(\ket0\) or \(\ket1\), and Z and the last H then give equal probabilities for both answers. The relative sign and the absence of a measurement in the middle are both needed.

5.2.3 Phase and output probabilities§

In the NOT program, Z reversed the sign of the amplitude at \(1\), and the answer flipped. What happens between no sign change and a full one? Replace Z by a phase gate \(R_\phi\), which leaves \(\ket0\) alone and multiplies the amplitude of \(\ket1\) by \(e^{i\phi}\):

\[R_\phi\ket0=\ket0,\qquad R_\phi\ket1=e^{i\phi}\ket1.\]

The factor has magnitude one, so the gate preserves length. At \(\phi=0\) it is I, and at \(\phi=\pi\) it is Z. For input zero,

\[\ket0\xrightarrow{H}\frac{\ket0+\ket1}{\sqrt2}\xrightarrow{R_\phi}\frac{\ket0+e^{i\phi}\ket1}{\sqrt2}\xrightarrow{H}\frac{1+e^{i\phi}}2\ket0+\frac{1-e^{i\phi}}2\ket1.\]

Squaring the final amplitudes gives the probabilities:

\[p(0)=\left|\frac{1+e^{i\phi}}2\right|^2=\frac{1+\cos\phi}{2},\qquad p(1)=\frac{1-\cos\phi}{2}.\]

At \(\phi=0\) the output is certainly zero, at \(\phi=\pi\) certainly one, and at \(\phi=\pi/2\) the two are equally likely. Just before the final H, the state has the same probabilities \(1/2,1/2\) for every \(\phi\). The last gate turns a relative phase that no measurement could see into the probabilities of the answer.

5.3

Pauli Operators

Our one-qubit programs used H, X, Z, and the family \(R_\phi\). How many different single-qubit operations are there, and can a few fixed ones describe them all? We first complete the family that X and Z begin, then show that four matrices describe every operator, and finally separate describing an operation from building it out of gates.

5.3.1 The Pauli operators§

X exchanges the two configurations, and Z changes their relative sign. Is there an operation that does both at once? Apply Z and then X:

\[XZ\ket0=X\ket0=\ket1,\qquad XZ\ket1=X(-\ket1)=-\ket0.\]

It exchanges the configurations and gives them opposite signs. But X and Z each undo themselves, while \(XZ\) does not: \((XZ)^2\ket0=XZ\ket1=-\ket0\), so \((XZ)^2=-I\). Multiplying by \(i\) repairs this, since \((iXZ)^2=i^2(XZ)^2=I\). We define

\[Y=iXZ,\qquad Y\ket0=i\ket1,\qquad Y\ket1=-i\ket0.\]

X, Y, and Z are the Pauli operators. With the identity I, their matrices in the basis \(\ket0,\ket1\) are

\[I=\begin{pmatrix}1&0\\0&1\end{pmatrix},\quad X=\begin{pmatrix}0&1\\1&0\end{pmatrix},\quad Y=\begin{pmatrix}0&-i\\i&0\end{pmatrix},\quad Z=\begin{pmatrix}1&0\\0&-1\end{pmatrix}.\]

Each column lists the amplitudes produced from one input configuration. On a general state,

\[X(a\ket0+b\ket1)=b\ket0+a\ket1,\quad Y(a\ket0+b\ket1)=-ib\ket0+ia\ket1,\quad Z(a\ket0+b\ket1)=a\ket0-b\ket1.\]

Each preserves length, and each undoes itself: \(X^2=Y^2=Z^2=I\). Does the order of two different Paulis matter? The calculation above shows \(XZ\ket0=\ket1\), while \(ZX\ket0=Z\ket1=-\ket1\); in general \(ZX=-XZ\). So a product of Paulis is again I, X, Y, or Z, times a phase factor. A phase factor common to the whole state does not change any outcome probability.

5.3.2 Describing every operator§

The phase gate \(R_\phi\) sat between I and Z. Can every single-qubit operator be written as a combination of I, X, Y, and Z? Take an arbitrary matrix

\[A=\begin{pmatrix}a&b\\c&d\end{pmatrix}.\]

The diagonal entries can come from I and Z: I adds equally to both, and Z adds with opposite signs. The off-diagonal entries can come from X and Y: X adds equally to both, and Y adds with opposite imaginary factors. Matching the four entries gives

\[A=\frac{a+d}{2}I+\frac{b+c}{2}X+\frac{c-b}{2i}Y+\frac{a-d}{2}Z.\]

Check the upper-right entry: \((b+c)/2-(c-b)/2=b\). The lower-left entry is \((b+c)/2+(c-b)/2=c\), and the diagonal entries are \(a\) and \(d\). The coefficients are unique, so I, X, Y, and Z form a basis for single-qubit operators. Here an operator is any linear map of state vectors, not necessarily a gate. For example,

\[H=\frac{X+Z}{\sqrt2},\qquad R_\phi=\frac{1+e^{i\phi}}2I+\frac{1-e^{i\phi}}2Z.\]

Does this mean a circuit of Pauli gates can perform H? No. The expansion adds matrices, while a circuit multiplies them: X followed by Z performs \(ZX\), not \((X+Z)/\sqrt2\). Choosing X or Z at random does not produce the sum either. Starting from \(\ket0\), any sequence of Pauli gates leaves a single basis state, up to a phase, so it never reaches \(H\ket0=(\ket0+\ket1)/\sqrt2\). Nor is every combination a gate: \(I+Z\) sends \(\ket0\) to \(2\ket0\) and \(\ket1\) to zero, which is not unitary.

Can we at least turn a state continuously using one Pauli? Define

\[R_x(\theta)=\cos(\theta/2)I-i\sin(\theta/2)X.\]

For real \(\theta\) it is unitary: multiplying by its adjoint, the cross terms cancel because \(X^2=I\), leaving \((\cos^2(\theta/2)+\sin^2(\theta/2))I=I\). It sends \(\ket0\) to \(\cos(\theta/2)\ket0-i\sin(\theta/2)\ket1\), so the amplitudes vary continuously with \(\theta\). A gate with an adjustable angle is a different capability from the fixed gate X.

So four matrices describe every single-qubit operator. Which operators a machine can build from the gates it has is a separate question.
