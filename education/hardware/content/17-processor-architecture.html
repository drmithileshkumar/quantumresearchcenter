17.1 Connectivity

The same logical circuit can require very different physical operations on different connection graphs. Architecture makes that difference explicit.

17.1.1 Local and nonlocal interactions

Represent available two-qubit interactions by edges between physical qubits. An edge also has a direction if the native gate requires one, a duration, and an error model. Some pairs share a mediator or control channel and cannot operate simultaneously even when they have no common qubit. A graph is therefore the beginning of a scheduling model, not the whole architecture.

17.1.2 Routing and scheduling

A gate between distant logical partners may require SWAPs, movement, or teleportation. A SWAP can be decomposed into three CNOTs when those CNOTs are available, but another platform may implement exchange directly. Track the mapping of logical states after every move; restoring the original mapping is sometimes unnecessary. The compilation objective must include idle errors and contention, not only the number of added gates.

Problem 17.1. On a line A–B–C, how can an A–C interaction be made local?

Worked solution

Swap A and B, then interact the state now at B with C. A restoring SWAP is needed only if the later schedule requires the original placement. In a CNOT decomposition one SWAP costs three CNOTs.

17.2 Modular Systems

17.2.1 Photonic links

An optical link can establish an entangled pair between modules. If independent attempts succeed with probability \(p\) and take time \(\tau\), the mean waiting time is \(\tau/p\), neglecting other overhead. This geometric waiting time has a broad distribution. Heralded availability must enter the schedule, and successful pairs may need storage while other links are being prepared.

17.2.2 Communication and memory

Local memory competes with link waiting time. Parallel attempts can improve availability but need extra communication qubits, optics, and routing. Entanglement purification can improve state quality at a resource cost under suitable noise assumptions. A modular design should state which qubits communicate, which compute, how they exchange states, and what happens to the computation when a link attempt fails.

Problem 17.2. A link succeeds with probability 0.02 per 10 μs attempt. Find its mean waiting time.

Worked solution

It is 10 μs/0.02 = 500 μs under independent trials, with no extra reset or communication delay. A memory requirement cannot be inferred from this mean alone; long waits also occur.

17.3 Scaling Design

17.3.1 Fabrication and yield

If every component independently works with probability \(y\), the probability that all \(N\) work is \(y^N\). This simple yield model motivates spare components and defect-tolerant layouts. Real defects can be correlated, so the independent estimate is only a starting point. A large fabricated array and a large usable connected array are different achievements.

17.3.2 Architecture-aware resource counts

Start a resource estimate from a compiled workload: count active qubits, communication and syndrome auxiliaries, routed gates, measurement rounds, and elapsed time. Then include failures, retries, and calibration. Compare designs at a matched target output accuracy. The architecture that minimizes physical qubits may not minimize time or total spacetime use, especially when communication or auxiliary-state preparation dominates.

Problem 17.3. For 1,000 independent components of yield 0.999, estimate perfect-array yield.

Worked solution

It is 0.999¹⁰⁰⁰ ≈ 0.368. Redundancy and repairable connectivity can be essential even when individual yield is high.
