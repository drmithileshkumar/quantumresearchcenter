We have met codes that detect errors: the three-bit repetition code, the binomial code in an oscillator, the grid code. Each relies on measurements that reveal an error without revealing the encoded information. On hardware, those measurements are themselves circuits made of noisy gates and noisy readouts. Can a device check for errors without adding more errors than it removes?

We first build a parity check from two CNOTs and an auxiliary qubit, and see why it preserves superpositions. Because the check can itself fail, we repeat it, and asking how errors move through CNOTs shows how one fault can spread. Code distance then says how many errors a code can correct, and asking how logical gates and special auxiliary states are supplied gives their cost in space and time. Finally, leakage, correlations, and latency shape real performance, and asking when a larger code actually helps leads to the threshold and the overhead of a long computation.

Our first question is how a device can learn whether two bits agree without learning either bit.

18.1 Syndrome Extraction

A parity measurement should reveal whether two data bits agree without revealing either bit. How can gates and one auxiliary qubit do that, and what happens when they fail? Two CNOTs copy the parity onto the auxiliary, and linearity shows that superpositions within each parity sector survive. Repeating the check guards against faulty reports, but CNOTs can also spread a single fault to several qubits.

18.1.1 Physical parity circuits

How can a device learn whether two bits agree without learning either? Prepare an auxiliary qubit in \(\ket0\) and apply two CNOTs, with data qubits \(x\) and \(y\) as controls and the auxiliary as target. The first writes \(x\) onto the auxiliary, and the second adds \(y\) modulo two, leaving \(\ket{x,y,x\oplus y}\). Measuring the auxiliary therefore records whether \(x\) and \(y\) agree, without measuring either one.

What happens to a superposition? By linearity, \(a\ket{00}+b\ket{11}\) leaves the auxiliary in \(\ket0\), so its coherence survives. The odd sector \(a\ket{01}+b\ket{10}\) leaves the auxiliary in \(\ket1\). A superposition across the two sectors is projected onto one of them, which is what a parity check should do. The recorded bit is the eigenvalue of \(Z_1Z_2\), with auxiliary bit 0 for \(+1\) and 1 for \(-1\). The ideal circuit is the specification that a physical implementation must meet.

18.1.2 Measurement faults and repetition

If a reported parity changes between rounds, did the data change? Not necessarily: one of the two reports may have been wrong. Repeating the check gives a history that helps tell these apart. For three independent reports of a constant parity, each wrong with probability \(e\), a majority vote fails with probability \(3e^2(1-e)+e^3\), the repetition-code formula again. At \(e=0.01\) that is 0.000298.

Predict before calculating. If an auxiliary parity report changes, does that prove a data qubit has flipped?

Compare your reasoning

No. A measurement fault can change the reported bit. Repeated extraction provides information about both data and measurement faults.

Is repetition enough? The constant-parity assumption is strong, since data errors can occur during the three measurements. Errors also move through gates. How does an X error on the control of a CNOT move? Check on basis states: \(\mathrm{CNOT}\,(X\otimes I)\,\mathrm{CNOT}\ket{c,t}=\ket{c\oplus1,t\oplus1}\), so \(\mathrm{CNOT}\,X_1\,\mathrm{CNOT}=X_1X_2\). An X on the control before the gate equals an X on both qubits after it. In the same way \(\mathrm{CNOT}\,Z_2\,\mathrm{CNOT}\ket{c,t}=(-1)^{c\oplus t}\ket{c,t}\), so a Z on the target spreads to both. An auxiliary fault partway through a check can therefore reach more than one data qubit, depending on the order of the gates. Repetition alone does not make a check fault-tolerant.

Problem 18.1. What happens when the parity circuit receives (|00⟩ + |11⟩)/√2?

Worked solution

Both components put the auxiliary in zero, so its measurement leaves their superposition intact in the ideal circuit. Measuring the two data qubits individually would instead reveal which component was present.

18.2 Logical Operations

Checks tell us that errors occurred; a code must also decide which errors to undo, and it must let us compute. How many errors can a code correct, and how are logical gates performed? Code distance bounds the correctable errors when syndromes are perfect. Logical gates and the auxiliary states some of them consume then cost cycles and space.

18.2.1 Code distance and decoding

How many errors can a code correct? Call a Pauli product a logical Pauli if it changes the encoded information while leaving every check unchanged. The code distance \(d\) is the smallest number of qubits such a nontrivial operator acts on. Suppose two candidate errors each act on at most \(t\) qubits. If both produce the same syndrome, their product leaves every check unchanged and acts on at most \(2t\) qubits. When \(2t<d\), that product cannot be a nontrivial logical Pauli, so undoing either candidate gives the same encoded state. A distance-\(d\) code therefore corrects up to \(\lfloor(d-1)/2\rfloor\) arbitrary qubit errors, given ideal syndromes and a suitable recovery.

What changes when the syndromes are noisy? The decoder must then interpret changes across rounds, in space and time together, rather than trust one set of readouts. A single faulty entangling gate can also create several data errors, so faulty circuit locations are not the same as independent errors on the final qubits. The code, the schedule, the noise, and the decoder together decide the logical performance.

18.2.2 Gates and auxiliary states

How do we compute on encoded qubits? A logical gate must change the encoded state while keeping faults under control. A transversal gate acts separately on corresponding physical qubits of the code blocks, so a fault on one qubit cannot spread within its block. Other constructions move code boundaries, or measure joint logical observables between neighbouring patches of code. These procedures take cycles and temporary physical space.

What do non-Clifford gates cost? Some constructions consume a specially prepared auxiliary state for each such gate. A dedicated region that produces these states is called a factory. If a factory delivers one usable state every \(F\) cycles but the algorithm requests one every \(A\) cycles, then when \(F>A\) the computation must slow down or add factories. An ideal gate count that omits this production misses a possible bottleneck. We do not derive a universal fault-tolerant gate set here, only the accounting that any chosen construction must satisfy.

Problem 18.2. How many arbitrary physical-qubit errors can a distance-5 code correct with perfect syndrome information?

Worked solution

At most floor((5−1)/2) = 2. This does not mean that every pair of faulty circuit locations is harmless; faults can propagate to multiple data qubits.

18.3 Hardware Requirements

Distance counts independent Pauli errors, but hardware errors are not always independent or Pauli. Which hardware effects break the counting, and when does a larger code help at all? Leakage and shared failures produce errors that are correlated in time and space, and decoding takes time. Comparing codes of different distance then defines the threshold and sets the overhead of a long computation.

18.3.1 Leakage, correlation, and latency

What does a leaked qubit do to the checks? Suppose a leaked data qubit persists for many rounds and interacts with each fresh auxiliary. The resulting syndrome faults are strongly correlated in time, even though the leakage event itself was rare. Likewise, one failure of a shared control can affect many qubits in the same cycle. A fit with independent Pauli errors can miss both mechanisms.

So repeated extraction is measured in its full simultaneous context, with reset, leakage removal, readout crosstalk, and decoding deadlines included. A pipelined decoder can process checks continuously while correction is delayed, but operations that need a resolved result still wait for it. The useful figure is the logical error per cycle together with the cycle duration, since trading one against the other changes the reliability per unit of elapsed time.

18.3.2 Thresholds and overhead

When does a larger code help? A larger distance needs more qubits and more gates, hence more places where faults can occur. It also needs more faults before correction fails. If the physical error rate \(p\) is low, the second effect wins and the logical error falls as \(d\) grows; if \(p\) is high, the first wins and it rises. The crossover value \(p_{\rm th}\) is called the threshold.

How fast does the logical error fall below threshold? A distance-\(d\) code with \(d\) odd fails only when about \((d+1)/2\) faults occur together. This motivates the fit \(p_L\simeq A(p/p_{\rm th})^{(d+1)/2}\), where \(A\) and \(p_{\rm th}\) summarize the code, circuit, and decoder. It is a fitted model for a local-error regime, not a theorem.

What does a long computation require? With \(A=0.1\) and \(p/p_{\rm th}=0.1\), raising the distance from three to five changes the estimate from \(10^{-3}\) to \(10^{-4}\). If \(K\) logical cycles fail independently with probability \(p_L\), keeping the total failure below \(\epsilon\) requires approximately \(Kp_L\le\epsilon\) when errors are small. With \(K=10{,}000\) and \(\epsilon=0.01\), the target is about \(10^{-6}\) per cycle. So a good single-cycle number can still imply a large overhead in distance, and therefore in qubits.

Problem 18.3. Use \(A=0.1\), \(p/p_{\rm th}=0.1\). Compare distances 3 and 5 in the illustrative fit.

Worked solution

The estimates are \(10^{-3}\) and \(10^{-4}\). Increasing distance improves this model at the cost of more qubits and operations; a real estimate must validate its noise assumptions.
