Reading guide · preparation and approach

Starting point: Earlier programming chapters; relevant constructions from Quantum Computing and Quantum Algorithms.

Anchor example: Package a complete algorithm implementation with tests, execution records, and analysis.

This lesson includes explanations, worked examples, and problems with solutions. Advanced results whose proofs are outside the chapter are identified explicitly.

16.1 Project Structure

A project is reproducible when another reader can reconstruct its task, circuit, assumptions, and evidence. A plot without the program and execution record is not enough.

16.1.1 Modules, notebooks, and tests

Keep circuit factories, experiment drivers, and tests separate. A notebook can explain an experiment, while a script runs it from a fresh process. Tests should include a small independently solvable case, asymmetric ordering checks, and phase-sensitive inputs. Never make importing a module submit a hardware job.

16.1.2 Dependencies and version control

Pin tested dependencies and record the Python version. Keep credentials out of version control. Record source changes so that a result points to the code that produced it. A requirements file captures direct dependencies; a full environment lock and platform note improve exact reproduction. Updating a package requires rerunning relevant examples rather than assuming unchanged behavior.

Problem 16.1. Why does the target bit vary in the capstone output?

Worked solution

It remains in minus, which gives a fair computational-basis result. The useful secret is in the other bits, so the decoder excludes the target bit.

16.2 Experiment Records

16.2.1 Saved circuits and configurations

Save a circuit artifact as well as its drawing. QPY preserves Qiskit circuit structure for supported version compatibility, and the companion checks an in-memory save/load round trip. Keep the logical circuit, compiled circuit, layout, parameter values, and seeds when compilation is involved. A diagram alone may omit global phases or parameter metadata.

16.2.2 Results, metadata, and execution costs

An experiment record should identify the problem, input size, access assumptions, success criterion, shots, qubits, logical and compiled counts, execution type, package versions, and measured outputs. Exact local simulation, noisy simulation, and hardware must be labeled distinctly. Confidence intervals and error budgets belong beside conclusions, not hidden in raw logs.

Problem 16.2. What changes if the secret is all zeros?

Worked solution

The oracle has no CNOTs and the input Hadamards cancel, so the output secret is all zeros. This is an important edge case.

16.3 Capstone Project

16.3.1 Specification and implementation

The capstone implements Bernstein–Vazirani for an arbitrary supplied binary secret. It prepares a minus target, uses one CNOT for each one bit in the oracle description, applies Hadamards, and reads the input register. The known secret lets us verify construction; it is not being discovered by a program that lacks access to its own source. The algorithmic query model treats the constructed oracle as the supplied interface.

16.3.2 Evaluation, limitations, and documentation

The companion uses secret 1011, checks circuit serialization, samples, and verifies every input-register result. The target is measured too and appears at the left of Qiskit’s full string; bits[1:] extracts the input register. Extend the project across lengths, test zero and all-one secrets, report oracle gate growth, and compare with the classical query baseline under the same oracle contract. The result is a reproducible implementation study, not a hardware speedup claim.

The complete companion below can be downloaded as chapter_16.py. Run it from a terminal using the course environment. Assertions check the stated behavior; printed counts are samples, not universal expected output.

"""Runnable companion for Quantum Programming, Chapter 16."""
import io, json, sys
from importlib.metadata import version
from qiskit import QuantumCircuit, qpy
from qiskit.primitives import StatevectorSampler
from qiskit.quantum_info import Operator

secret = "1011"  # Written high bit first.
n = len(secret)
qc = QuantumCircuit(n+1)
qc.x(n); qc.h(range(n+1))
for qubit, bit in enumerate(reversed(secret)):
    if bit == "1":
        qc.cx(qubit, n)
qc.h(range(n))
# Save/load the coherent circuit before appending measurements.
buffer = io.BytesIO()
qpy.dump(qc, buffer); buffer.seek(0)
restored = qpy.load(buffer)[0]
assert Operator(qc).equiv(Operator(restored))
qc.measure_all()
counts = StatevectorSampler(seed=41).run([qc], shots=1024).result()[0].data.meas.get_counts()
assert all(bits[1:] == secret for bits in counts)
record = {"problem": "Bernstein-Vazirani", "secret": secret,
    "python": sys.version.split()[0], "qiskit": version("qiskit"),
    "seed": 41, "shots": 1024, "qubits": qc.num_qubits,
    "gate_counts": dict(qc.count_ops()), "counts": counts,
    "execution": "local ideal StatevectorSampler", "oracle_queries_per_shot": 1}
print(json.dumps(record, indent=2))

Problem 16.3. What evidence would be needed for a runtime advantage claim?

Worked solution

A scalable task and access model, matched classical baseline, complete preparation and oracle costs, execution and readout costs, comparable success and precision, and measurements or justified resource analysis over growing sizes.

1. Quick check §

For the capstone’s Bernstein–Vazirani construction, which input qubits receive CNOTs to the target for the secret 0110? What should the input register read?

Hint 1

The secret is written high bit first and reversed when assigning qubits.

Hint 2

Qubit \(k\) gets a CNOT if bit \(k\) (from the right) is \(1\).

Worked solution

Reading 0110 from the right, bits \(1\) and \(2\) are \(1\), so qubits 1 and 2 control CNOTs onto the target. The input register then reads 0110 with certainty (in Qiskit’s order, qubit 0 rightmost), and the full measured string has the target bit on the left.

from qiskit import QuantumCircuit
from qiskit.primitives import StatevectorSampler

def bernstein_vazirani(secret):
    n = len(secret)
    circuit = QuantumCircuit(n + 1)
    circuit.x(n)
    circuit.h(range(n + 1))
    for qubit, bit in enumerate(reversed(secret)):
        if bit == "1":
            circuit.cx(qubit, n)
    circuit.h(range(n))
    return circuit

circuit = bernstein_vazirani("0110")
controls = [circuit.find_bit(i.qubits[0]).index for i in circuit.data if i.operation.name == "cx"]
assert controls == [1, 2]
circuit.measure_all()
counts = StatevectorSampler(seed=1).run([circuit], shots=256).result()[0].data.meas.get_counts()
assert all(bits[1:] == "0110" for bits in counts)

2. Quick check §

For an \(n\)-bit secret with \(k\) ones, count the gates of the capstone circuit (before measurement). Check the counts and the depth for the all-ones secret with \(n=10\).

Hint 1

One X, \(n+1\) Hadamards before, \(n\) after, and \(k\) CNOTs.

Hint 2

All CNOTs share the target, so they run sequentially.

Worked solution

The circuit has \(1\) X, \(2n+1\) Hadamards, and \(k\) CNOTs. For \(n=10\), \(k=10\): \(21\) H, \(10\) CNOTs, depth \(13\), since the CNOTs all target the same qubit and run one after another. The query count is one, but the oracle’s gate count and depth grow with the secret, which a resource report must include.

from qiskit import QuantumCircuit

def bernstein_vazirani(secret):
    n = len(secret)
    circuit = QuantumCircuit(n + 1)
    circuit.x(n)
    circuit.h(range(n + 1))
    for qubit, bit in enumerate(reversed(secret)):
        if bit == "1":
            circuit.cx(qubit, n)
    circuit.h(range(n))
    return circuit

circuit = bernstein_vazirani("1" * 10)
assert dict(circuit.count_ops()) == {"h": 21, "cx": 10, "x": 1} and circuit.depth() == 13

3. Quick check §

A project records the Qiskit version but not the versions of Aer, NumPy, or the Python interpreter. Which results could fail to reproduce, and what file in this course records the complete environment?

Hint 1

Simulators, random-number streams, and numerical libraries all have versions.

Hint 2

The course keeps two dependency files.

Worked solution

Noisy-simulation results depend on the Aer version; numerical tolerances and random streams can change with NumPy and Python; even ideal sampling with a fixed seed can differ between versions of the primitives. requirements.txt pins the direct dependencies, and requirements-lock.txt records the full resolved environment, while TESTING.md notes the platform. A record should cite all of them.

4. Worked problem §

Turn the capstone into a tested function. (a) Write bernstein_vazirani(secret) and a check that samples the circuit and verifies the input register for every shot. (b) Apply it to 0000, 1111, and three random six-bit secrets from a seeded generator. (c) Why include the all-zero and all-one secrets?

Hint 1

Use bits[1:] to drop the target bit.

Hint 2

Edge cases test the empty oracle and the busiest oracle.

Worked solution

The function passes for all five secrets. The all-zero secret has no CNOTs at all, so it checks that the Hadamard layers alone return \(\ket{0^n}\) and that an empty oracle does not break the construction; the all-one secret exercises every CNOT and the longest sequential chain on the target. Random secrets cover typical cases. Edge cases and random cases together make a stronger test than the single secret in the companion.

import random
from qiskit import QuantumCircuit
from qiskit.primitives import StatevectorSampler

def bernstein_vazirani(secret):
    n = len(secret)
    circuit = QuantumCircuit(n + 1)
    circuit.x(n)
    circuit.h(range(n + 1))
    for qubit, bit in enumerate(reversed(secret)):
        if bit == "1":
            circuit.cx(qubit, n)
    circuit.h(range(n))
    circuit.measure_all()
    return circuit

def recovers(secret, seed=41):
    counts = StatevectorSampler(seed=seed).run([bernstein_vazirani(secret)], shots=256).result()[0].data.meas.get_counts()
    return all(bits[1:] == secret for bits in counts)

rng = random.Random(7)
secrets = ["0000", "1111"] + ["".join(rng.choice("01") for _ in range(6)) for _ in range(3)]
assert all(recovers(secret) for secret in secrets)

5. Worked problem §

Verify the oracle’s phase contract directly: after the oracle acts on the uniform input with the target in \(\ket-\), the input amplitudes should be \((-1)^{s\cdot x}/2^{n/2}\). Implement the check for the secret 1011 by returning the target to \(\ket0\) and comparing the statevector with the predicted sign pattern.

Hint 1

After the oracle, H and then X on the target return \(\ket-\) to \(\ket0\).

Hint 2

\(s\cdot x\) is the parity of the bitwise AND of the integers.

Worked solution

Undoing the target preparation leaves the state \(\sum_x(-1)^{s\cdot x}\ket x/4\otimes\ket0\). Comparing the first \(16\) amplitudes (target \(0\)) with \((-1)^{\mathrm{popcount}(s\,\&\,x)}/4\) confirms the phase oracle exactly. This tests the oracle’s promised behavior independently of the final Hadamards, so a failure would point to the oracle rather than to the readout.

import numpy as np
from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector

secret = "1011"
n = len(secret)
s = int(secret, 2)
circuit = QuantumCircuit(n + 1)
circuit.x(n)
circuit.h(range(n + 1))
for qubit, bit in enumerate(reversed(secret)):
    if bit == "1":
        circuit.cx(qubit, n)
circuit.h(n)
circuit.x(n)
amplitudes = Statevector.from_instruction(circuit).data[: 2 ** n]
expected = np.array([(-1) ** bin(s & x).count("1") for x in range(2 ** n)]) / 2 ** (n / 2)
assert np.allclose(amplitudes, expected)

6. Worked problem §

Build an experiment record for the capstone that a reader can verify. Include the problem, secret, shots, seed, and package versions for qiskit, qiskit-aer, and numpy, and add a SHA-256 fingerprint of the QPY-serialized coherent circuit. Why is the fingerprint useful?

Hint 1

importlib.metadata.version reads installed versions.

Hint 2

Hash the QPY bytes with hashlib.

Worked solution

The record below stores the descriptive fields, the versions, and a hash of the serialized circuit. The fingerprint identifies exactly which circuit produced the results: if someone later regenerates the circuit and the hash differs, something in the construction or the software changed. Storing the QPY file itself lets them load and rerun that exact circuit. (QPY files can depend on the Qiskit version, so the version belongs next to the hash.)

import hashlib, io, json
from importlib.metadata import version
from qiskit import QuantumCircuit, qpy

secret = "1011"
n = len(secret)
circuit = QuantumCircuit(n + 1)
circuit.x(n)
circuit.h(range(n + 1))
for qubit, bit in enumerate(reversed(secret)):
    if bit == "1":
        circuit.cx(qubit, n)
circuit.h(range(n))
buffer = io.BytesIO()
qpy.dump(circuit, buffer)
record = {
    "problem": "Bernstein-Vazirani", "secret": secret, "shots": 1024, "seed": 41,
    "versions": {name: version(name) for name in ("qiskit", "qiskit-aer", "numpy")},
    "circuit_sha256": hashlib.sha256(buffer.getvalue()).hexdigest(),
    "execution": "local ideal StatevectorSampler",
}
assert len(record["circuit_sha256"]) == 64
print(json.dumps(record, indent=2))

7. Worked problem §

Run the capstone (secret 1011) on a noisy simulator in which every CNOT suffers two-qubit depolarizing error \(0.02\). (a) Estimate the fraction of shots whose input register equals the secret. (b) Why is it below \(1\), and how would it change for a longer secret with more ones? (c) How should the result be labelled?

Hint 1

Three CNOTs each carry error \(0.02\).

Hint 2

Errors grow with the number of ones in the secret.

Worked solution

(a) About \(0.96\) with \(8000\) shots. (b) Each of the three CNOTs fails with probability about \(0.02\), and many failures corrupt the readout, so success is roughly \(1-3\times0.02\times(\text{fraction harmful})\). A secret with \(k\) ones has \(k\) noisy CNOTs, so success falls roughly linearly in \(k\) for small errors. (c) As a noisy simulation with a stated, hypothetical noise model, distinct from both ideal simulation and hardware, with the model parameters, seed, and shots recorded.

from qiskit import QuantumCircuit, transpile
from qiskit_aer import AerSimulator
from qiskit_aer.noise import NoiseModel, depolarizing_error

secret = "1011"
n = len(secret)
circuit = QuantumCircuit(n + 1)
circuit.x(n)
circuit.h(range(n + 1))
for qubit, bit in enumerate(reversed(secret)):
    if bit == "1":
        circuit.cx(qubit, n)
circuit.h(range(n))
circuit.measure_all()
noise = NoiseModel()
noise.add_all_qubit_quantum_error(depolarizing_error(0.02, 2), ["cx"])
sim = AerSimulator(noise_model=noise, seed_simulator=3, max_parallel_threads=1)
shots = 8000
counts = sim.run(transpile(circuit, sim, optimization_level=0), shots=shots).result().get_counts()
success = sum(count for bits, count in counts.items() if bits[1:] == secret) / shots
assert 0.9 < success < 0.99

8. Misconception §

A student argues: “The capstone finds a \(50\)-bit secret with one query, while a classical algorithm needs \(50\), so this project demonstrates a quantum speedup.” List what the project actually demonstrates and what a speedup claim would require.

Hint 1

The oracle was built from the known secret.

Hint 2

Compare end-to-end costs under the same access model.

Worked solution

The project demonstrates a correct, reproducible implementation of the algorithm in the query model, where the oracle is a supplied interface. Here the oracle was constructed from the known secret, with one CNOT per one-bit, so reading the circuit reveals the secret and building it costs as many gates as the classical queries it replaces. A speedup claim would need a setting where the oracle is genuinely given as a black box, matched classical and quantum access, end-to-end costs including oracle construction and noise, and measured performance as \(n\) grows, not a single success.

9. Extension §

Extend the capstone study to \(n=50\). (a) Why is a statevector simulation impossible, and why can Aer’s stabilizer method still run the circuit? (b) Run it for the secret “10” repeated \(25\) times and check the result. (c) What does this say about choosing a simulation method in a scaling study?

Hint 1

The circuit uses only X, H, and CNOT.

Hint 2

A statevector of \(51\) qubits needs \(2^{51}\) amplitudes.

Worked solution

(a) \(51\) qubits need \(2^{51}\approx2\times10^{15}\) amplitudes, about \(36\) petabytes. The circuit uses only Clifford gates (X, H, CNOT), which the stabilizer method simulates with polynomial resources. (b) Every shot returns the secret in the input register. (c) The simulator must match the circuit class: stabilizer methods scale for Clifford circuits, tensor networks for low-entanglement ones, statevectors for small general circuits. A scaling study should state which was used, since simulation cost is a property of the method, not evidence about quantum hardware.

from qiskit import QuantumCircuit
from qiskit_aer import AerSimulator

secret = "10" * 25
n = len(secret)
circuit = QuantumCircuit(n + 1)
circuit.x(n)
circuit.h(range(n + 1))
for qubit, bit in enumerate(reversed(secret)):
    if bit == "1":
        circuit.cx(qubit, n)
circuit.h(range(n))
circuit.measure_all()
counts = AerSimulator(method="stabilizer").run(circuit, shots=20, seed_simulator=1).result().get_counts()
assert {bits[1:] for bits in counts} == {secret}

10. Extension §

Design the directory layout and test plan for turning the capstone into a reusable project. Name the modules, what each test checks, and how hardware submission is kept from happening by accident.

Hint 1

Separate circuit factories, experiment drivers, and tests.

Hint 2

Keep submission behind an explicit flag.

Worked solution

A reasonable layout: a package module with the circuit factory (bernstein_vazirani) and the oracle; an experiment driver script that builds, compiles, runs, and writes a JSON record and QPY file; a tests directory with exact tests (phase contract, statevector output for small \(n\), edge-case secrets), seeded sampling tests, a noisy-simulation smoke test, and a serialization round-trip test; and requirements and lock files with a README describing the environment. The driver submits to hardware only with an explicit option and backend name, and importing any module never submits. Continuous testing reruns the suite whenever dependencies change.
