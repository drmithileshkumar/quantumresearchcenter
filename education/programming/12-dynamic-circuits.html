How can a measurement change the remaining computation?

Reading guide · preparation and approach

Starting point: Earlier programming chapters; relevant constructions from Quantum Computing and Quantum Algorithms.

Anchor example: Implement teleportation with measurement-dependent corrections.

This lesson includes explanations, worked examples, and problems with solutions. Advanced results whose proofs are outside the chapter are identified explicitly.

Until now, every measurement came at the end of a circuit. Its result went back to the host program, which could only print it or analyse it. Some devices can do more: measure a qubit partway through, and let the result decide which gates come next, while the other qubits are still in use.

How can a measurement change the remaining computation? We first meet the two operations involved, mid-circuit measurement and reset. Using a result inside the circuit runs into the old problem that a host-language if cannot see a result that does not yet exist, so we need a condition recorded in the circuit itself. Teleportation then gives a program with four measurement branches, each needing its own correction, and we must check that every branch is right, not just the average. Finally, a simulator that accepts such a circuit does not show that a device can run it, so we look at the constraints that real controllers impose.

Teleportation is a demanding test, because a single wrong correction would break exactly one branch.

12.1 Mid-Circuit Operations

A circuit with a measurement in the middle keeps running after the measurement. What becomes of the measured qubit and its result, and how can later gates use that result? We look at the measurement and the reset first, then at conditions that read a measured bit.

12.1.1 Measurement and reset

What does a measurement in the middle of a circuit do? It writes a classical bit, and it leaves the measured qubit in the basis state it reported. The other qubits stay available for later gates. A reset then puts a qubit back in \(\ket0\), so that it can be reused. If that qubit was entangled with others, the reset destroys the correlation, as we saw when we found that a reset has no inverse. Both are physical operations on a device. Neither is a Python assignment.

Which simulator can run such circuits? StatevectorSampler is meant for circuits measured only at the end. For circuits whose later gates depend on mid-circuit results, the companion uses Aer’s AerSimulator. It follows each shot down the branch selected by that shot’s measurement results.

12.1.2 Classical conditions and feedback

Suppose we want a qubit to end in \(\ket0\) whatever it held: measure it, and apply X if the result was 1. Could we write that with an ordinary Python if bit == 1: qc.x(0)? No. That line runs at construction time, when the circuit has not been executed and no bit exists. The condition has to be part of the circuit, so that the controller evaluates it during the run.

Qiskit writes such a condition as a block:

with qc.if_test((qc.clbits[0], 1)):
    qc.x(0)

Python’s with statement opens a context, and the indented lines run inside it. Here the context is if_test, and it changes what appending means. The gates appended inside the block are not applied unconditionally. They are recorded into the circuit as the body of a condition. The tuple (qc.clbits[0], 1) names the condition: classical bit 0 equals 1. Using a measurement result to choose later operations is called feedback, or feedforward. The condition must name the exact classical bit that the measurement map writes to.

12.2 Conditional Programs

With feedback we can program protocols that branch on measurement results. Teleportation is the standard example: Alice sends a qubit’s state to Bob using a shared Bell pair and two classical bits. Which correction belongs to which bit, and how can a program show that all four branches work? We derive the corrections first, then verify each branch.

12.2.1 Teleportation

The companion places the input \(\ket\psi=\alpha\ket0+\beta\ket1\) on q0. A Bell pair \((\ket{00}+\ket{11})/\sqrt2\) is made on q1 and q2 with H on q1 and a CNOT from q1 to q2. Alice holds q1, and Bob holds q2. Alice then applies a CNOT from q0 to q1 and H on q0, and measures q0 into c0 and q1 into c1. Call those results \(m\) and \(n\). The figure uses the same names.

What state does Bob hold in each branch? Writing the qubits in the order q0, q1, q2, the CNOT gives \[\tfrac1{\sqrt2}\bigl[\alpha\ket0(\ket{00}+\ket{11})+\beta\ket1(\ket{10}+\ket{01})\bigr].\] H on q0 replaces \(\ket0\) by \((\ket0+\ket1)/\sqrt2\) and \(\ket1\) by \((\ket0-\ket1)/\sqrt2\). Collecting the terms by the values \(m,n\) of q0 and q1, Bob’s qubit is left in

\[m n=00:\ \alpha\ket0+\beta\ket1,\quad 01:\ \alpha\ket1+\beta\ket0,\quad 10:\ \alpha\ket0-\beta\ket1,\quad 11:\ \alpha\ket1-\beta\ket0,\]

each with probability \(1/4\). These are \(X^nZ^m\ket\psi\). So Bob applies X when \(n=1\) and then Z when \(m=1\). This gives \(Z^mX^n\,X^nZ^m\ket\psi=\ket\psi\) exactly in every branch.

In the program, the two corrections are two if_test blocks, on qc.clbits[1] for X and on qc.clbits[0] for Z. Exchanging the two records would apply the wrong correction in branches 01 and 10.

Problem 12.1. Why apply Z controlled by c0 rather than c1?

Worked solution

The H measurement on the original input determines the phase correction. The Bell-half measurement determines the bit-flip correction. Swapping these records fails on general input states.

12.2.2 Verifying every branch

How can a program check that Bob holds \(\ket\psi\)? We cannot read amplitudes from a measurement. But if \(\ket\psi\) was made by a known preparation \(V\ket0\), then applying \(V^\dagger\) to Bob’s qubit returns it to \(\ket0\) exactly when the state is right. A measurement then gives 0 with certainty.

The companion prepares \(\ket\psi\) with \(R_y(0.7)\) and then \(R_z(0.4)\), so the state has unequal amplitudes and a nontrivial relative phase. After the corrections it applies \(R_z(-0.4)\) and then \(R_y(-0.7)\) to Bob’s qubit, and measures it into c2. Every shot, in every branch, should give c2 = 0.

Why insist on the phase? A missing Z correction changes only the sign of \(\beta\). On a basis state such as \(\ket0\) that change is invisible, and on any state with real amplitudes it is a different but plausible state. A test state with a relative phase exposes it. One test state still does not determine the whole process. Stronger validation repeats the test with other preparations, or with an input entangled with a reference qubit.

Problem 12.2. Does Bob receive the state before Alice communicates her outcomes?

Worked solution

Without the records his state is averaged over the four Pauli branches. The corrections require those classical bits, so the protocol does not signal instantly.

12.3 Execution Constraints

Our teleportation program runs on a simulator. A device has to do something harder: measure, send the bit to a classical controller, decide, and apply a gate, all while the other qubits wait. What does that require of a device, and what does it change about how we judge correctness? We take capabilities first, then timing and branch-by-branch checking.

12.3.1 Simulator and backend capabilities

If Aer accepts our if_test blocks, will a device accept them too? Not necessarily. A simulator implements the abstract circuit, while a device’s controller supports only certain conditions, certain resets and certain timing. Before submitting, we check what the chosen backend supports. A controller may evaluate only simple classical expressions, so a high-level condition may have to be rewritten. The companion runs locally and says nothing about hardware availability.

12.3.2 Latency, branches, and correctness

What does feedback cost? It can save qubits or depth. A measured and reset qubit can be reused, for example, instead of allocating a new one. But each measurement and each classical decision takes time, called latency, and the waiting qubits are exposed to noise during it.

How do we read the companion’s counts? Each key lists the classical bits as c2 c1 c0, with c0 on the right, as in our bit-order convention. So key[0] is c2, the verification bit. With seed 23 the run gave about 250 counts in each of the four branches c1 c0 = 00, 01, 10, 11, because Alice’s outcomes are random. Every key began with 0.

The final assertion requires key[0] == "0" for every key that appeared, using all, which is true only if the test holds for every item. It is a check on every observed branch. A check on the overall fraction of zeros could pass even if one rare branch were always wrong. The circuit is first passed through transpile(qc, sim), which rewrites it in the simulator’s supported instructions. Aer then returns counts through result().get_counts(), an older result interface than the primitives use.

"""Runnable companion for Quantum Programming, Chapter 12."""
from qiskit_aer import AerSimulator
from qiskit import QuantumCircuit, transpile

# q0=input, q1=Alice's half, q2=Bob's half; c0,c1 are correction records.
qc = QuantumCircuit(3, 3)
qc.ry(0.7, 0); qc.rz(0.4, 0)
qc.h(1); qc.cx(1, 2)
qc.cx(0, 1); qc.h(0)
qc.measure(0, 0); qc.measure(1, 1)
with qc.if_test((qc.clbits[1], 1)):
    qc.x(2)
with qc.if_test((qc.clbits[0], 1)):
    qc.z(2)
# Inverse of the known test preparation verifies the recovered state.
qc.rz(-0.4, 2); qc.ry(-0.7, 2)
qc.measure(2, 2)
sim = AerSimulator(seed_simulator=23, max_parallel_threads=1)
counts = sim.run(transpile(qc, sim), shots=1024).result().get_counts()
assert all(key[0] == "0" for key in counts)
print("c2 c1 c0:", counts)

Problem 12.3. Why test a nontrivial phase as well as real amplitudes?

Worked solution

A missing Z correction may be invisible on a basis state. A phase-sensitive input exposes that error.

A program whose logic is correct can still give wrong counts on a device, because the device is noisy. When a result disagrees with our prediction, how can we tell a noisy experiment from an incorrect program?

Sources and further study: IBM, classical feedforward.

1. Quick check §

In the companion’s teleportation, Alice obtains \(c_0=1\) and \(c_1=0\). Which state does Bob hold before correction, and which correction does the program apply?

Hint 1

Bob’s branch operator is \(X^{c_1}Z^{c_0}\).

Hint 2

Only the Z condition fires.

Worked solution

Bob holds \(Z\ket\psi\) (branch operator \(X^0Z^1\)). The \(X\) condition on \(c_1\) does not fire, the \(Z\) condition on \(c_0\) does, and \(Z\cdot Z\ket\psi=\ket\psi\). The verification measurement on Bob then gives \(0\).

2. Quick check §

Prepare a Bell pair and reset qubit 0. Using DensityMatrix.evolve, find the joint state afterwards. What happened to qubit 1’s reduced state and to the correlation?

Hint 1

Reset maps either value of qubit 0 to \(\ket0\).

Hint 2

Qubit 1’s reduced state was \(I/2\) before.

Worked solution

The joint state becomes \(\ket0\bra0\otimes I/2\): qubit 0 is \(\ket0\), qubit 1 is maximally mixed, and the correlation is gone. Qubit 1’s reduced state is unchanged, as no-signalling requires, but the reset destroyed the entanglement. Reset is a physical, irreversible operation, not a reassignment of a variable.

import numpy as np
from qiskit import QuantumCircuit
from qiskit.quantum_info import DensityMatrix

circuit = QuantumCircuit(2)
circuit.h(0)
circuit.cx(0, 1)
circuit.reset(0)
state = DensityMatrix.from_label("00").evolve(circuit)
assert np.allclose(state.data, np.diag([0.5, 0, 0.5, 0]))

3. Quick check §

The companion’s counts are written c2 c1 c0. Decode the key 010: which corrections were applied on those shots, and did the verification succeed?

Hint 1

The leftmost character is c2.

Hint 2

c1 controls X and c0 controls Z.

Worked solution

c2 \(=0\), c1 \(=1\), c0 \(=0\). Alice’s records called for an X correction and no Z correction, and the verification bit c2 \(=0\) shows that Bob’s corrected state matched the input. Decoding must use the register order; reading the key left to right as c0, c1, c2 would misidentify both the branch and the result.

4. Worked problem §

Swap the correction rules in the teleportation program, so that X is conditioned on c0 and Z on c1. Run it in Aer and inspect the verification bit for each branch. Which branches fail, and why does one branch still pass?

Hint 1

The correct correction for branch \((c_0,c_1)\) is \(X^{c_1}\) then \(Z^{c_0}\).

Hint 2

For branch \(11\), \(XZ\) and \(ZX\) differ only by a sign.

Worked solution

Branches \(c_1c_0=00\) and \(11\) still verify (c2 \(=0\)): branch \(00\) needs no correction, and in branch \(11\) the swapped rules apply both corrections in the opposite order, which differs only by a global sign. Branches \(01\) and \(10\) receive the wrong Pauli and fail most of the time. A test that only looked at the aggregate success fraction could be fooled; checking every branch separately exposes the bug immediately.

from qiskit import QuantumCircuit, transpile
from qiskit_aer import AerSimulator

def teleport(swap_rules):
    qc = QuantumCircuit(3, 3)
    qc.ry(0.7, 0); qc.rz(0.4, 0)
    qc.h(1); qc.cx(1, 2)
    qc.cx(0, 1); qc.h(0)
    qc.measure(0, 0); qc.measure(1, 1)
    x_bit, z_bit = (0, 1) if swap_rules else (1, 0)
    with qc.if_test((qc.clbits[x_bit], 1)):
        qc.x(2)
    with qc.if_test((qc.clbits[z_bit], 1)):
        qc.z(2)
    qc.rz(-0.4, 2); qc.ry(-0.7, 2)
    qc.measure(2, 2)
    sim = AerSimulator(seed_simulator=23, max_parallel_threads=1)
    return sim.run(transpile(qc, sim), shots=2048).result().get_counts()

assert all(key[0] == "0" for key in teleport(False))
bad = teleport(True)
failed_branches = {key[1:] for key in bad if key[0] == "1"}
assert failed_branches == {"01", "10"}

5. Worked problem §

Rewrite teleportation with deferred measurement: replace the classically conditioned X and Z by cx(1, 2) and cz(0, 2) applied before any measurement. Verify with Statevector that, after the inverse test preparation on Bob’s qubit, Bob always reads \(0\). What practical difference remains between the two versions?

Hint 1

Deferred measurement replaces classical control by quantum control.

Hint 2

Check the marginal probabilities of qubit 2.

Worked solution

With cx(1, 2) and cz(0, 2) in place of the conditional corrections, Bob’s qubit ends in \(\ket\psi\) for every branch, and after the inverse preparation it reads \(0\) with probability \(1\); the circuit no longer needs mid-circuit measurement or feedback. The difference is physical: the deferred version needs quantum two-qubit gates between Alice’s and Bob’s qubits, so it cannot be used at a distance, while the dynamic version needs only classical communication, at the cost of measurement and feedback latency.

import numpy as np
from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector

deferred = QuantumCircuit(3)
deferred.ry(0.7, 0); deferred.rz(0.4, 0)
deferred.h(1); deferred.cx(1, 2)
deferred.cx(0, 1); deferred.h(0)
deferred.cx(1, 2)
deferred.cz(0, 2)
deferred.rz(-0.4, 2); deferred.ry(-0.7, 2)
bob = Statevector.from_instruction(deferred).probabilities_dict(qargs=[2])
assert np.isclose(bob["0"], 1)

6. Worked problem §

Reuse one qubit for two independent random bits: apply H, measure into c0, reset, apply H again, and measure into c1. Run it in Aer and check that the four outcomes are about equally frequent. Is the reset necessary here? Would it be if the second H were replaced by ry(\(\pi/3\))?

Hint 1

After the first measurement the qubit is \(\ket0\) or \(\ket1\).

Hint 2

ry(\(\pi/3\)) gives \(P(1)=\frac14\) from \(\ket0\) but \(\frac34\) from \(\ket1\).

Worked solution

The four outcomes occur about \(1000\) times each in \(4000\) shots: two independent fair bits from one qubit. In this particular example the reset happens not to matter, because H maps both \(\ket0\) and \(\ket1\) to states with equal probabilities. With ry(\(\pi/3\)) as the second step it would matter: from \(\ket0\) the second bit is \(1\) with probability \(\frac14\), but from \(\ket1\) with probability \(\frac34\), so without reset the second bit would depend on the first. Reset returns the reused qubit to the known state that the next step assumes; mid-circuit measurement and reset let a small device act like a larger one over time.

from qiskit import QuantumCircuit, transpile
from qiskit_aer import AerSimulator

circuit = QuantumCircuit(1, 2)
circuit.h(0)
circuit.measure(0, 0)
circuit.reset(0)
circuit.h(0)
circuit.measure(0, 1)
sim = AerSimulator(seed_simulator=23, max_parallel_threads=1)
counts = sim.run(transpile(circuit, sim), shots=4000).result().get_counts()
assert set(counts) == {"00", "01", "10", "11"} and all(abs(n - 1000) < 150 for n in counts.values())

7. Worked problem §

Implement active reset with feedback: prepare \(\ket+\), measure into c0, and apply X if c0 is \(1\); then measure again into c1. Show that c1 is always \(0\). How does this differ from the reset instruction, and what can make it fail on hardware?

Hint 1

After measuring 1, X returns the qubit to \(\ket0\).

Hint 2

Consider measurement error and latency.

Worked solution

The second measurement always gives \(0\) in simulation: the qubit is returned to \(\ket0\) whatever the first outcome. This is how reset is often implemented physically. On hardware it fails when the first measurement reports the wrong value (the correction is then applied or skipped wrongly), when the qubit relaxes or is excited during the feedback delay, or when the measurement leaves it outside the qubit subspace. The reset instruction hides these details, but they still set its error rate.

from qiskit import QuantumCircuit, transpile
from qiskit_aer import AerSimulator

circuit = QuantumCircuit(1, 2)
circuit.h(0)
circuit.measure(0, 0)
with circuit.if_test((circuit.clbits[0], 1)):
    circuit.x(0)
circuit.measure(0, 1)
sim = AerSimulator(seed_simulator=23, max_parallel_threads=1)
counts = sim.run(transpile(circuit, sim), shots=1000).result().get_counts()
assert all(key[0] == "0" for key in counts)

8. Misconception §

A student says: “I don’t need feedforward for teleportation. I can run the circuit without corrections and afterwards keep only the shots where Alice measured 00.” Compare the fraction of usable shots in the two approaches, and explain why the postselected version is not teleportation.

Hint 1

Each of Alice’s four outcomes occurs with probability \(\frac14\).

Hint 2

Bob must act on the qubit during the run to use it later.

Worked solution

Postselection keeps only the \(25\%\) of shots in branch \(00\), and it decides after the run which shots to keep: in any single run Bob’s qubit was wrong three times out of four, and he could not have used it for anything before the data were sorted. Feedforward corrects every branch during the run, so all shots deliver the state and Bob’s qubit is usable immediately. Postselection estimates what teleportation would give; it does not perform the task.

9. Extension §

In dynamic teleportation, Bob’s qubit must wait for Alice’s measurement (\(1\) μs) and the classical decision (\(0.5\) μs). (a) With \(T_2=100\) μs, estimate the coherence loss during the wait. (b) Compare with the deferred version, which instead adds two two-qubit gates with error \(5\times10^{-3}\) each. (c) Which is better here, and what changes the answer?

Hint 1

Loss \(\approx1-e^{-t/T_2}\).

Hint 2

Two gates contribute about \(10^{-2}\).

Worked solution

(a) \(1-e^{-1.5/100}\approx1.5\times10^{-2}\). (b) About \(10^{-2}\) from the two extra gates, if the qubits can interact at all. (c) Here the deferred version is slightly better, but only when quantum gates between the parties are possible; with faster feedback or longer \(T_2\), the dynamic version wins, and at a distance it is the only option. Latency is a resource to budget, like gate error.

10. Extension §

Validate teleportation more strongly by teleporting half of an entangled pair. Let qubit 3 be a reference entangled with the input qubit 0 in a Bell state. After teleportation and corrections, undo the Bell preparation on the reference and Bob’s qubit and measure both. What outcome indicates success, and why is this test stronger than teleporting one known state?

Hint 1

Undo the Bell preparation with cx(3, 2) then h(3).

Hint 2

A channel that preserves entanglement preserves every input state.

Worked solution

After corrections, cx(3, 2) and h(3) map the reference–Bob Bell pair back to \(\ket{00}\), so both final measurements give \(0\) on every shot. Preserving entanglement with an untouched reference tests the channel on all input states at once (it is equivalent to checking the full process), whereas one known test state checks only one input. Any error that would corrupt some inputs shows up as nonzero outcomes here.

from qiskit import QuantumCircuit, transpile
from qiskit_aer import AerSimulator

qc = QuantumCircuit(4, 4)
qc.h(3); qc.cx(3, 0)            # reference q3 entangled with input q0
qc.h(1); qc.cx(1, 2)            # Alice q1, Bob q2
qc.cx(0, 1); qc.h(0)
qc.measure(0, 0); qc.measure(1, 1)
with qc.if_test((qc.clbits[1], 1)):
    qc.x(2)
with qc.if_test((qc.clbits[0], 1)):
    qc.z(2)
qc.cx(3, 2); qc.h(3)
qc.measure(2, 2); qc.measure(3, 3)
sim = AerSimulator(seed_simulator=23, max_parallel_threads=1)
counts = sim.run(transpile(qc, sim), shots=2048).result().get_counts()
assert all(key[:2] == "00" for key in counts)
