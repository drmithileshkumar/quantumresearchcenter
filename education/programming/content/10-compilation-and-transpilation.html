10.1 Backend Targets

A circuit requests CNOT between qubits zero and two, but the device has only a line of neighboring qubits. Compilation must change the implementation while preserving the logical computation.

10.1.1 Native operations

A backend target describes supported operations and the qubits on which they can act, often with timing and calibration information. A list of native gate names is not enough to describe all device constraints. The example uses a simple line coupling graph and an explicit gate basis so the routing problem is visible without contacting hardware.

10.1.2 Connectivity and device constraints

Connectivity can force swaps or equivalent routing operations. Native entangling directions may also require extra gates. These costs depend on both the circuit and the chosen placement. Logical qubits are variables in the algorithm; physical qubits are execution locations. Their correspondence can change during compilation.

Problem 10.1. Why may a native gate count exceed a logical count?

Worked solution

A logical gate may require decomposition or routing. The two counts use different operation vocabularies.

10.2 Transpilation

10.2.1 Decomposition and synthesis

Decomposition breaks a composite operation into smaller pieces. Synthesis constructs a sequence approximating a specified transformation within an error target. Transpilation can combine these with layout, routing, and simplification. Optimization levels select strategies; a larger level is not a proof of a smaller or better circuit for every instance.

10.2.2 Layout, routing, and optimization

An initial layout assigns logical wires to physical positions. Routing may leave a final permutation. Comparing compiled matrices without accounting for that mapping can report a false error. The companion uses Operator.from_circuit so the circuit’s layout is interpreted, then checks equivalence with the original logical operator.

Problem 10.2. What does an optimization level guarantee?

Worked solution

It selects a compilation strategy; it does not certify a globally minimal circuit or better physical performance on every backend.

10.3 Compiler Inspection

10.3.1 Pass managers

A pass manager organizes analysis and transformation passes. Fixing seed_transpiler makes randomized choices reproducible within the tested implementation. Inspect the resulting layout, operation counts, and depth rather than treating compilation as a black box. Run several seeds only if that search effort is included in the reported classical cost.

10.3.2 Logical equivalence and physical resource counts

The example compiles a three-qubit circuit to rz, sx, x, and cx on a line. It prints logical and compiled counts and checks semantic equivalence. For larger circuits, full matrices may be impossible; use component proofs, structured tests, and observable checks with stated limits. Resource estimates should include added ancillas, routing, synthesis precision, and the target model.

The complete companion below can be downloaded as chapter_10.py. Run it from a terminal using the course environment. Assertions check the stated behavior; printed counts are samples, not universal expected output.

"""Runnable companion for Quantum Programming, Chapter 10."""
import numpy as np
from qiskit import QuantumCircuit, transpile
from qiskit.transpiler import CouplingMap
from qiskit.quantum_info import Operator

qc = QuantumCircuit(3)
qc.h(0)
qc.cx(0, 2)
compiled = transpile(qc, basis_gates=["rz", "sx", "x", "cx"],
    coupling_map=CouplingMap.from_line(3), initial_layout=[0, 1, 2],
    optimization_level=1, seed_transpiler=19)
logical = Operator.from_circuit(compiled)
assert logical.equiv(Operator(qc))
print("Logical", qc.count_ops(), "compiled", compiled.count_ops())
print("Layout:", compiled.layout)

Problem 10.3. Why record the layout with an experiment?

Worked solution

It tells which physical wires realize the logical ones and is needed to interpret observables and sometimes output mappings correctly.

Compilation prepares a device-compatible workload. Hardware execution adds account access, budgets, and provenance.
