6.1 Execution Primitives

For Ry(θ)|0〉, the probability of one is sin²(θ/2), while the mean of Z is cos θ. These are two ways to ask about the same circuit, and they correspond to two execution interfaces.

6.1.1 V2 Sampler and Estimator

A Sampler accepts measured circuits and returns shot records. An Estimator accepts circuits together with observables and returns expectation estimates. V2 interfaces group related work in primitive unified blocs, usually abbreviated PUBs. A PUB is an input grouping, not a quantum gate or a physical batch guarantee. The companion uses local Statevector implementations, so no device account is involved.

6.1.2 Local implementations and result structures

The Estimator input tuple contains a circuit, an observable, and parameter values. The result is indexed by input PUB; data.evs holds the corresponding expectation array. For Sampler, data is organized by classical register name; measure_all creates meas in our examples. Explicitly named registers change the field you read. Do not paste a result-access expression without checking the circuit’s register names.

Problem 6.1. At θ=π/3, predict p(1) and the Z mean.

Worked solution

They are 1/4 and 1/2. A result near zero would suggest a wrong angle, observable, or parameter mapping.

6.2 Statistical Readout

6.2.1 Shots, precision, and uncertainty

A Bernoulli frequency has variance \(p(1-p)/R\), while an average of ±1 values has variance \((1-\langle Z\rangle^2)/R\). The identity \(\langle Z\rangle=1-2p(1)\) connects them. Exact StatevectorEstimator at zero requested precision has no shot fluctuation for our unitary examples; it is not a model of a hardware estimator with finite shots.

6.2.2 Bit strings and classical postprocessing

Decode counts using the measurement mapping before converting them into an observable. For two bits, ZZ assigns +1 to equal bits and −1 to unequal bits. Summing signed counts and dividing by total shots estimates its mean. A normalized count table is an empirical distribution; its small entries have large relative uncertainty.

Problem 6.2. How does doubling shots change a standard error?

Worked solution

It reduces the standard error by √2, assuming independent identically distributed shots. It does not remove systematic bias.

6.3 Repeated Workloads

6.3.1 Parameter sweeps

The companion sends angles 0, π/2, and π as a three-row parameter array. Its returned Z means must be 1, 0, and −1. Parameter sweeps reuse a circuit structure while changing values. Array shapes describe the experiment and should be checked explicitly; silently broadcasting the wrong dimension can produce a different workload.

6.3.2 Batching inputs and interpreting results

Batching several experiments can reduce host overhead, but each requested circuit, parameter set, observable group, and shot budget still consumes resources. Keep the parameter order and result order in the saved record. The example separates an exact three-point sweep from a sampled midpoint, so the two sources of output are unambiguous.

The complete companion below can be downloaded as chapter_06.py. Run it from a terminal using the course environment. Assertions check the stated behavior; printed counts are samples, not universal expected output.

"""Runnable companion for Quantum Programming, Chapter 6."""
import numpy as np
from qiskit import QuantumCircuit
from qiskit.circuit import Parameter
from qiskit.primitives import StatevectorSampler, StatevectorEstimator
from qiskit.quantum_info import SparsePauliOp

theta = Parameter("theta")
qc = QuantumCircuit(1)
qc.ry(theta, 0)
values = [[0], [np.pi / 2], [np.pi]]
result = StatevectorEstimator().run([(qc, SparsePauliOp("Z"), values)]).result()
assert np.allclose(result[0].data.evs, [1, 0, -1])
measured = qc.assign_parameters({theta: np.pi / 2})
measured.measure_all()
counts = StatevectorSampler(seed=9).run([measured], shots=4096).result()[0].data.meas.get_counts()
print("Exact means:", result[0].data.evs, "sampled counts:", counts)

Problem 6.3. Why keep a circuit without measurements for the Estimator?

Worked solution

It represents the prepared state whose observable is requested. The estimation implementation chooses its measurement procedure; terminal measurements in the input can conflict with that contract.
