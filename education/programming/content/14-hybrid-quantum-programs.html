14.1 Parameterized Workflows

A variational program repeatedly prepares a parameterized state and asks for its energy. Start with an objective whose entire curve is known, so the optimizer cannot conceal an implementation mistake.

14.1.1 Parameter binding and objectives

Prepare cos(θ/2)|00〉+sin(θ/2)|11〉 using Ry on qubit zero followed by CNOT. For H=−ZZ−XX, the energy is −1−sin θ. The minimum −2 occurs at θ=π/2. This analytic curve is the oracle for testing the program; the numerical search should reproduce it before any larger problem is attempted.

14.1.2 Repeated estimation

Keep the circuit symbolic and bind parameters through the primitive’s input array. Each evaluation has a cost, even if the host loop is short. The companion evaluates a grid in one local Estimator workload. Exact local expectations remove shot noise from this first debugging stage; a hardware experiment would need a measurement allocation and confidence analysis.

Problem 14.1. Why is the energy at θ=0 equal to −1?

Worked solution

The state is 00, so ZZ has expectation one and XX has expectation zero.

14.2 Optimization Loops

14.2.1 Gradients and classical updates

For a single Pauli-generated rotation, the derivative is half the difference of energies at θ±π/2. A gradient step subtracts a learning-rate multiple of that derivative. A grid search is simpler for the one-parameter example and gives a reproducible baseline. Large parameter spaces require more careful optimization, but complicated optimizers do not fix a wrong circuit or objective.

14.2.2 Stopping criteria and reproducibility

Stop according to an energy-improvement and uncertainty criterion, plus an evaluation budget. Fix initial points and random seeds when comparing methods. A noisy objective can have biased gradients and flat regions. Record failed runs and initialization sensitivity; choosing only the best seed after many attempts understates classical and quantum costs.

Problem 14.2. Can a measured energy below −2 be accepted as a better solution?

Worked solution

Not for this exact Hamiltonian. It indicates statistical fluctuation, bias, or a programming error; the true minimum is −2.

14.3 Applications

14.3.1 Variational eigensolvers

A variational eigensolver is a trial family, observable estimator, and classical parameter search. The variational bound says each exact trial energy is at least the ground energy; it does not guarantee that the family contains the ground state or that optimization finds its best member. Noisy estimates can violate that bound numerically without violating quantum mechanics.

14.3.2 QAOA and performance comparisons

QAOA changes the trial family to alternating cost and mixer evolutions. Compare its output distribution with a classical heuristic on the same instances and include training evaluations. The companion’s solved two-qubit energy demonstrates a correct loop interface, not quantum advantage. It verifies the whole sampled parameter grid against the analytic curve and reports the minimum.

The complete companion below can be downloaded as chapter_14.py. Run it from a terminal using the course environment. Assertions check the stated behavior; printed counts are samples, not universal expected output.

"""Runnable companion for Quantum Programming, Chapter 14."""
import numpy as np
from qiskit import QuantumCircuit
from qiskit.circuit import Parameter
from qiskit.primitives import StatevectorEstimator
from qiskit.quantum_info import SparsePauliOp

theta = Parameter("theta")
qc = QuantumCircuit(2)
qc.ry(theta, 0); qc.cx(0, 1)
H = SparsePauliOp.from_list([("ZZ", -1), ("XX", -1)])
angles = np.linspace(0, np.pi, 101)
energies = StatevectorEstimator().run([(qc, H, angles[:, None])]).result()[0].data.evs
assert np.allclose(energies, -1 - np.sin(angles))
best = int(np.argmin(energies))
assert np.isclose(energies[best], -2)
print("Grid minimum:", angles[best], energies[best])

Problem 14.3. Why keep a grid baseline?

Worked solution

It provides a transparent reference on the small problem and exposes errors in sophisticated optimization machinery. Its cost grows rapidly with parameter dimension, so it is not a general scalable strategy.
