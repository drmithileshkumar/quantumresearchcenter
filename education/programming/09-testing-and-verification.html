Reading guide · preparation and approach

Starting point: Earlier programming chapters; relevant constructions from Quantum Computing and Quantum Algorithms.

Anchor example: Find a circuit bug that passes basis-probability tests but fails on superpositions.

This lesson includes explanations, worked examples, and problems with solutions. Advanced results whose proofs are outside the chapter are identified explicitly.

9.1 Functional Tests

A wrong circuit can pass every computational-basis probability test. Identity and Z are the simplest example: they preserve basis labels but disagree on plus. Verification must test the kind of behavior the component promises.

9.1.1 Basis inputs and superpositions

A basis test should compare complex output amplitudes when checking a coherent contract. If it compares only measured labels, it may miss input-dependent phases. Superpositions make those phases visible. The companion first confirms that I and Z have identical basis output probabilities, then shows that their actions on plus are inequivalent.

9.1.2 Equivalence and global phase

A whole circuit can differ by one global phase without changing its standalone output statistics. Operator.equiv recognizes that freedom. An independent phase on each input column is not a global phase. Moreover, controlling a unitary turns its global phase into a relative control phase. The companion checks both cases, so a tolerance or equivalence shortcut does not erase meaningful distinctions.

Problem 9.1. Why does testing Z on zero miss the bug?

Worked solution

Zero is an eigenstate of Z with eigenvalue one. Test plus to expose the relative sign between zero and one.

9.2 State and Workspace Checks

9.2.1 Register ordering and ancilla cleanup

Use asymmetric inputs to test ordering. Check the probability of nonzero scratch outcomes, the reduced target state, and the final joint state when small enough. A clean workspace should factor from the useful registers. Basis tests for a fixed initialized workspace certify only that subspace, which is appropriate if the interface explicitly requires that initialization.

9.2.2 Inverse and composition tests

Test inverse and composition identities, but pair them with a specification test. U followed by its computed inverse is identity even if U implements the wrong function. Composition can also reveal incompatible wire contracts or omitted phase conventions. Random complex inputs are useful additional checks, not a substitute for a proof or a complete small matrix test.

Problem 9.2. Can two individually global-equivalent gates always be substituted under control?

Worked solution

No. Their differing phase acts only in the control-one branch and becomes observable relative to the control-zero branch.

9.3 Statistical Tests

9.3.1 Numerical tolerances

Numerical tolerances should reflect floating-point accumulation and approximation error. Exact small gates can use tight absolute tolerances such as 10^-12; an intentionally approximate product formula needs its analytic error budget. Relative tolerance alone is unsuitable near a zero amplitude. Report which equivalence notion and norm the test uses.

9.3.2 Sampling uncertainty and regression tests

Sampling tests need statistical tolerances and can occasionally fail even for correct code. Fix seeds for regression reproducibility, but also check deterministic state or operator predictions. Avoid demanding exact counts from an ideal probabilistic experiment. The companion intentionally includes a wrong circuit and verifies that the meaningful coherent test rejects it.

The complete companion below can be downloaded as chapter_09.py. Run it from a terminal using the course environment. Assertions check the stated behavior; printed counts are samples, not universal expected output.

"""Runnable companion for Quantum Programming, Chapter 9."""
import numpy as np
from qiskit import QuantumCircuit
from qiskit.quantum_info import Operator, Statevector

identity = QuantumCircuit(1)
wrong = QuantumCircuit(1)
wrong.z(0)
# Basis output probabilities match, but relative phase differs.
for label in ("0", "1"):
    state = Statevector.from_label(label)
    assert np.allclose(state.evolve(identity).probabilities(), state.evolve(wrong).probabilities())
assert not Statevector.from_label("+").evolve(identity).equiv(Statevector.from_label("+").evolve(wrong))
assert not Operator(identity).equiv(Operator(wrong))
phase = QuantumCircuit(1)
phase.global_phase = 0.3
assert Operator(identity).equiv(Operator(phase))
assert not Operator(identity.to_gate().control()).equiv(Operator(phase.to_gate().control()))
print("Relative-phase bug detected; controlled global phase also checked")

Problem 9.3. Is a larger tolerance always safer?

Worked solution

It reduces false failures but can accept real bugs. Choose it from the numerical and approximation budgets, and include known incorrect examples that should fail.

1. Quick check §

A circuit should do nothing to one qubit, but a bug inserts an S gate. Which of these tests detects the bug: (a) basis-state output probabilities for \(\ket0\) and \(\ket1\); (b) statevector equivalence on \(\ket+\); (c) Operator equivalence?

Hint 1

S changes only the phase of \(\ket1\).

Hint 2

\(S\ket+=(\ket0+i\ket1)/\sqrt2\).

Worked solution

(a) Misses it: S leaves the basis probabilities unchanged. (b) Catches it: \(S\ket+=(\ket0+i\ket1)/\sqrt2\) is not equivalent to \(\ket+\). (c) Catches it: diag\((1,i)\) is not the identity up to a global phase. Tests of coherent components must include superposition inputs or full operators.

import numpy as np
from qiskit import QuantumCircuit
from qiskit.quantum_info import Operator, Statevector

identity = QuantumCircuit(1)
buggy = QuantumCircuit(1)
buggy.s(0)
for label in ("0", "1"):
    state = Statevector.from_label(label)
    assert np.allclose(state.evolve(identity).probabilities(), state.evolve(buggy).probabilities())
plus = Statevector.from_label("+")
assert not plus.evolve(identity).equiv(plus.evolve(buggy))
assert not Operator(identity).equiv(Operator(buggy))

2. Quick check §

Why does np.isclose(1e-17, 0, rtol=1e-9, atol=0) return False, while np.isclose(1e-17, 0, rtol=0, atol=1e-12) returns True? Which tolerance should an amplitude test use?

Hint 1

A relative tolerance scales with the size of the reference value.

Hint 2

The reference value here is \(0\).

Worked solution

With atol=0, the allowed difference is rtol times the magnitude of the reference value, which is \(0\), so even \(10^{-17}\) fails. An absolute tolerance of \(10^{-12}\) accepts floating-point noise. Amplitude tests should include an absolute tolerance, because many correct amplitudes are exactly zero and their computed values are tiny nonzero numbers (such as the \(10^{-33}\) entries seen in earlier chapters).

import numpy as np

assert not np.isclose(1e-17, 0, rtol=1e-9, atol=0)
assert np.isclose(1e-17, 0, rtol=0, atol=1e-12)

3. Quick check §

rz(0.4) and p(0.4) differ by a global phase. Does np.allclose on their Operator matrices succeed? Does Operator.equiv? Which comparison answers “are these the same standalone gate?”

Hint 1

\(R_z(\lambda)=e^{-i\lambda/2}P(\lambda)\).

Hint 2

equiv ignores a global phase.

Worked solution

np.allclose fails, because every entry differs by the factor \(e^{-0.2i}\). Operator.equiv succeeds, because it allows a global phase. equiv answers the standalone question; allclose answers the stricter question that matters when the gate will be controlled, where the two are genuinely different. A test must use the notion of equality that matches the gate’s intended use.

import numpy as np
from qiskit import QuantumCircuit
from qiskit.quantum_info import Operator

rz = QuantumCircuit(1)
rz.rz(0.4, 0)
p = QuantumCircuit(1)
p.p(0.4, 0)
assert not np.allclose(Operator(rz).data, Operator(p).data)
assert Operator(rz).equiv(Operator(p))

4. Worked problem §

Write a test that compares an implementation with its specification on a few random input states, using random_statevector with fixed seeds. Apply it to the S-gate bug of the quick check. Why are random states useful, and what do they not replace?

Hint 1

random_statevector(2, seed=...) gives a reproducible random state.

Hint 2

Compare state.evolve(implementation) with state.evolve(specification).

Worked solution

For each seeded random state, evolve it through both circuits and require equivalence; the S bug fails on every generic input, since a random state has both basis components. Random inputs exercise all relative phases at once and catch errors that special inputs such as \(\ket0\) hide. They do not replace an exhaustive operator check for small components, and they are not a proof: a bug confined to a tiny part of a large space may need many samples or a structured test.

from qiskit import QuantumCircuit
from qiskit.quantum_info import random_statevector

def agrees(implementation, specification, trials=5):
    n = specification.num_qubits
    for seed in range(trials):
        state = random_statevector(2 ** n, seed=seed)
        if not state.evolve(implementation).equiv(state.evolve(specification)):
            return False
    return True

specification = QuantumCircuit(1)
buggy = QuantumCircuit(1)
buggy.s(0)
assert agrees(specification, specification)
assert not agrees(buggy, specification)

5. Worked problem §

A test suite runs \(20\) independent sampling tests, each with a two-sided tolerance of \(z\) standard deviations. (a) For \(z=3\), each correct test fails with probability about \(0.0027\). What is the chance that a run of the whole suite has at least one false failure? (b) Repeat for \(z=4\) (each \(6.3\times10^{-5}\)). (c) What else should be done instead of simply raising \(z\)?

Hint 1

\(P(\text{some failure})=1-(1-p)^{20}\).

Hint 2

Higher \(z\) also makes real bugs harder to detect.

Worked solution

(a) \(1-0.9973^{20}\approx5.3\%\): one in twenty runs of a correct suite fails. (b) \(1-(1-6.3\times10^{-5})^{20}\approx0.13\%\). (c) Larger tolerances reduce false alarms but also hide small bugs. Better: test deterministic properties exactly with Statevector or Operator, use fixed seeds for regression tests of sampling code, and size the shot counts so that the bugs that matter remain detectable at the chosen \(z\).

6. Worked problem §

A product-formula simulation of \(e^{-i(X+Z)t}\) for \(t=1\) with \(r=10\) first-order steps has the error bound \(t^2\|[X,Z]\|/(2r)=0.1\). Write a test that compares the circuit’s operator with the exact exponential and uses this analytic bound as the tolerance. Check the actual error.

Hint 1

Build each step as rx(\(2t/r\)) followed by rz(\(2t/r\)) or equivalent.

Hint 2

Compute the exact unitary from the eigen-decomposition of \(X+Z\).

Worked solution

The circuit repeats ten steps of \(e^{-iX\delta}e^{-iZ\delta}\), implemented as rz(\(2\delta\)) then rx(\(2\delta\)), since \(R_x(\theta)=e^{-i\theta X/2}\). The exact unitary comes from diagonalizing \(X+Z\). The operator-norm error is about \(0.07\), within the bound \(0.1\), so the test passes. A tight tolerance such as \(10^{-12}\) would wrongly fail this correct approximate circuit; the tolerance must come from the approximation’s error budget.

import numpy as np
from qiskit import QuantumCircuit
from qiskit.quantum_info import Operator

t, r = 1.0, 10
delta = t / r
circuit = QuantumCircuit(1)
for _ in range(r):
    circuit.rz(2 * delta, 0)  # exp(-i Z delta) acts first
    circuit.rx(2 * delta, 0)  # then exp(-i X delta)
H = np.array([[1, 1], [1, -1]], dtype=complex)
values, vectors = np.linalg.eigh(H)
exact = vectors @ np.diag(np.exp(-1j * values * t)) @ vectors.conj().T
error = np.linalg.norm(Operator(circuit).data - exact, 2)
bound = t ** 2 * 2 / (2 * r)
assert error <= bound and error > 0.05

7. Worked problem §

A biased-coin bug shifts \(P(1)\) from \(0.50\) to \(0.48\). How many shots are needed for a test with a three-standard-deviation false-alarm threshold to detect this bug with \(90\%\) probability? Use \(N\approx\big((z_\alpha+z_\beta)\sigma/\delta\big)^2\) with \(z_\alpha=3\), \(z_\beta=1.28\), \(\sigma=0.5\), \(\delta=0.02\).

Hint 1

\((3+1.28)\times0.5/0.02\approx107\).

Hint 2

Square it.

Worked solution

\(N\approx107^2\approx1.1\times10^4\) shots. With the \(4096\) shots of earlier examples, the test would usually miss a \(2\%\) bias. Detection power must be planned: decide the smallest error that matters, then choose shots. When the property is deterministic, an exact Statevector check detects the bias without any shots.

8. Misconception §

A student argues: “If a test passes with a large tolerance, the circuit is correct; larger tolerances are just safer.” Using the S-gate bug, show a tolerance at which a statevector comparison on \(\ket+\) would pass, and explain why “safer” is the wrong word.

Hint 1

The S bug changes the \(\ket+\) output by a vector of length \(|1-i|/\sqrt2=1\).

Hint 2

Fidelity \(|\langle+|S|+\rangle|^2=\frac12\).

Worked solution

The outputs \(\ket+\) and \(S\ket+\) have fidelity \(\frac12\); a test that accepts any fidelity above \(0.4\), or any amplitude difference below \(1\), would pass the bug. A tolerance is not a safety margin: it defines which differences count as errors. It must be larger than numerical noise or approximation error, and much smaller than the smallest bug the test exists to catch. Too large is as wrong as too small.

9. Extension §

A subroutine is supposed to act only on qubits 0 and 1 of a three-qubit register. Write a test that verifies its Operator equals \(I\otimes U_{\rm sub}\), so that qubit 2 is untouched. What kinds of bugs does this catch that tests of the two-qubit block alone would not?

Hint 1

Operator(QuantumCircuit(1)).tensor(Operator(sub)) places the identity on qubit 2.

Hint 2

In Qiskit, the left tensor factor acts on the higher qubit index.

Worked solution

Comparing Operator(big) with Operator(I).tensor(Operator(sub)) checks that the embedded circuit acts as the subroutine on qubits 0, 1 and as the identity on qubit 2. It catches wrong wire mappings, gates accidentally applied to spectator qubits, and entanglement with the spectator (for example a stray CNOT onto qubit 2), none of which a test of the subroutine in isolation would see. The tensor order follows Qiskit’s convention that the left factor acts on the higher index.

from qiskit import QuantumCircuit
from qiskit.quantum_info import Operator

sub = QuantumCircuit(2)
sub.h(0)
sub.cx(0, 1)
big = QuantumCircuit(3)
big.compose(sub, qubits=[0, 1], inplace=True)
assert Operator(big).equiv(Operator(QuantumCircuit(1)).tensor(Operator(sub)))
leaky = big.copy()
leaky.cx(1, 2)
assert not Operator(leaky).equiv(Operator(QuantumCircuit(1)).tensor(Operator(sub)))

10. Extension §

Mutation testing measures a test suite by injecting small bugs. For the Bell circuit, consider four mutants: swap control and target; append Z on qubit 0; replace H by SX; drop the CNOT. Compare two tests: (a) “the counts contain only 00 and 11”; (b) statevector equivalence with \((\ket{00}+\ket{11})/\sqrt2\). How many mutants does each detect?

Hint 1

Appending Z gives \((\ket{00}-\ket{11})/\sqrt2\).

Hint 2

SX then CNOT gives \((\ket{00}-i\ket{11})/\sqrt2\).

Worked solution

Swapping control and target, or dropping the CNOT, produces outcomes 00 and 01, so test (a) catches both. Appending Z gives \((\ket{00}-\ket{11})/\sqrt2\), and SX gives \((\ket{00}-i\ket{11})/\sqrt2\): both still give only 00 and 11, so test (a) misses them. Test (b) catches all four. Mutation testing turns “my tests pass” into a measurable statement about which bugs they would catch, and shows that phase errors need phase-sensitive tests.

from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector

def bell(mutation=None):
    circuit = QuantumCircuit(2)
    circuit.sx(0) if mutation == "sx" else circuit.h(0)
    if mutation == "swap":
        circuit.cx(1, 0)
    elif mutation != "drop":
        circuit.cx(0, 1)
    if mutation == "z":
        circuit.z(0)
    return circuit

target = Statevector([2 ** -0.5, 0, 0, 2 ** -0.5])
def support_test(c):
    probabilities = Statevector.from_instruction(c).probabilities_dict()
    return all(p < 1e-12 for k, p in probabilities.items() if k not in ("00", "11"))
def state_test(c):
    return Statevector.from_instruction(c).equiv(target)

mutants = ["swap", "z", "sx", "drop"]
assert support_test(bell()) and state_test(bell())
assert sum(not support_test(bell(m)) for m in mutants) == 2
assert sum(not state_test(bell(m)) for m in mutants) == 4
