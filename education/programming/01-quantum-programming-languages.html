How should a programming language express quantum computation and its classical control?

Reading guide · preparation and approach

Starting point: Quantum Computing and Quantum Algorithms, or equivalent knowledge. Python is developed through examples in Chapter 2.

Anchor example: Compare descriptions of the same controlled operation and measurement in different programming styles.

This lesson includes explanations, worked examples, and problems with solutions. Advanced results whose proofs are outside the chapter are identified explicitly.

1.1 Language Families

A circuit drawing can say “apply H, then controlled-X, then measure.” A programming system must also decide what the qubits refer to, when measurements occur, and which instructions the hardware can execute. Language design makes these choices explicit.

1.1.1 Imperative and functional approaches

An imperative description lists actions on named registers in time order. A functional description emphasizes composition of transformations and return values. Both can describe the same Bell preparation: create two zeros, apply H to the first, and controlled-X to the second. The programming style does not change the underlying state. Functional interfaces can make composition and resource use explicit, while imperative interfaces often resemble the circuit directly.

1.1.2 Standalone languages and embedded frameworks

A standalone language has its own syntax and compiler; an embedded framework uses a host language to construct quantum instructions. Q# is a quantum programming language, OpenQASM describes circuit-level operations and classical control, and Qiskit is a Python SDK. A Python loop that appends gates runs while building a circuit; it is not automatically a loop executed by the quantum controller.

Problem 1.1. Does assigning other = circuit create an independent circuit?

Worked solution

No. Both Python names refer to the same mutable object. Use circuit.copy() when subsequent edits must be independent. Neither action copies a physical quantum state.

1.2 Design Principles

1.2.1 Types, ownership, and no-cloning

A qubit handle names a physical or logical resource. Assigning another variable to that handle does not copy its quantum state. Linear or affine type disciplines can restrict duplicated use or disposal of resources; no-cloning is a physical constraint even when a language does not enforce it statically. A robust interface also prevents accidentally using the same wire as both independent inputs to a gate.

1.2.2 Reversibility, measurement, and classical control

Unitary routines can have adjoints; a routine containing measurement or reset generally cannot be inverted as a unitary. Measurement produces a classical record that may select later operations. A host-language if statement on a circuit object cannot inspect an unexecuted qubit. Classical control during execution needs an instruction that refers to an actual recorded bit.

Problem 1.2. Can every quantum function have an automatic inverse?

Worked solution

Only operations with a specified reversible action can be inverted this way. Measurement with a discarded outcome and reset lose information in the circuit-level description.

1.3 Abstraction and Execution

1.3.1 Circuit languages and intermediate representations

An intermediate representation preserves the operations and dependencies while a compiler changes their implementation. Logical H and CNOT gates may become native rotations and entangling gates with inserted routing. The language should separate a circuit’s mathematical meaning from its device-specific realization. Exporting a circuit does not guarantee that every destination supports its timing or control constructs.

1.3.2 Qiskit as a Python SDK

The companion builds a Bell circuit in Python, then asks a simulator for its state. The function returns a description, while Statevector performs a classical calculation of that description. The two roles are separate. Predict amplitudes (1/√2,0,0,1/√2) before running it; only then use the assertion as a check.

The complete companion below can be downloaded as chapter_01.py. Run it from a terminal using the course environment. Assertions check the stated behavior; printed counts are samples, not universal expected output.

"""Runnable companion for Quantum Programming, Chapter 1."""
from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector

# A Python function builds a circuit; it does not execute a quantum device.
def bell():
    circuit = QuantumCircuit(2)
    circuit.h(0)
    circuit.cx(0, 1)
    return circuit

circuit = bell()
assert Statevector.from_instruction(circuit).equiv(
    Statevector([2**-0.5, 0, 0, 2**-0.5]))
print(circuit.draw(output="text"))

Problem 1.3. Why distinguish construction time from execution time?

Worked solution

The host may expand a loop into a fixed gate sequence before any quantum run. A measurement-dependent loop requires controller support and cannot be resolved during ordinary circuit construction.
