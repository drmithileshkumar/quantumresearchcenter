When does adding protection improve a computation, and what does that protection cost?

Reading guide · preparation and approach

Starting point: Chapters 1–9; error probabilities, logical circuits, and resource-state accounting.

Anchor example: An explicitly hypothetical surface-code model and a small concatenation recurrence.

Method: Budget total failure probability, invert a declared scaling model, and expose omitted resources.

Watch for: A threshold is tied to a noise model, code family, decoder, and circuit; it is not a universal device number.

This lesson includes explanations, worked examples, and problems with solutions. Advanced results whose proofs are outside the chapter are identified explicitly.

A code can reduce one memory error probability. A useful quantum computer must do more: it must execute a long sequence of operations with a sufficiently small chance that any damaging logical error spoils the answer. How small is sufficiently small, and how much protection must we buy? Those questions require a budget, not just a statement that the physical error rate is “low.”

Predict. If each of a million logical opportunities fails with probability 10⁻⁶, does that constitute a highly reliable computation?

10.1 Why a threshold can exist

10.1.1 Suppress faults faster than we add locations

A distance-three fault-tolerant gadget is designed so that one physical fault cannot cause logical failure on valid inputs. Under a suitable local stochastic model, its leading dangerous events therefore involve at least two faults. A simplified bound takes the form p₁≤Ap², where A accounts for dangerous pairs and any higher-order contributions absorbed into the bound’s range of validity.

If the same construction can be concatenated consistently, each encoded location is replaced by another level of protection. The illustrative recursion pₗ₊₁≤Apₗ² gives

\[p_\ell\le\frac1A(Ap)^{2^\ell}.\]

Check the first step: at ℓ=0 this is p; at ℓ=1 it is Ap². If Ap<1, repeated squaring drives the bound down rapidly. If Ap>1, this bound provides no suppression guarantee. For A=100 and p=0.001, the successive bounds are 10⁻⁴, 10⁻⁶, and 10⁻¹⁰. These numbers illustrate the mechanism, not a certified threshold for a specific architecture.

A threshold theorem makes such an argument rigorous for specified gadgets and noise assumptions, controlling dependencies and composing corrections with logical gates. For local stochastic noise, a useful assumption bounds the probability that every location in any chosen set S is faulty by p^|S|; this allows some correlations but excludes arbitrary common-cause failures of large sets at probability p. Other threshold theorems use other models. See Aliferis, Gottesman, and Preskill for a distance-three construction and its analysis.

Neither the simple recurrence nor a theorem supplies a universal experimental threshold. Leakage, biased noise, long-range correlations, scheduling, decoding, and available operations can change the applicable model. The first task in using a threshold is to identify which assumptions your system actually satisfies.

Worked check 10.1. Why does A count more than the code’s number of physical qubits?

Reasoned solution

Faults occur at circuit locations: gates, preparations, measurements, and idle intervals. Dangerous combinations depend on the complete gadget and its decoder, not just the data-block size. Two implementations of the same code can therefore have different effective bounds.

10.2 Budgeting an entire computation

10.2.1 Invert a scaling model with units attached

Suppose a computation has N logical failure opportunities, each with probability at most pL. The union bound gives total failure probability at most NpL. Independence is not required for that inequality. To allocate an error budget ε, a sufficient condition is pL≤ε/N. Other errors, such as gate-synthesis approximation and state-preparation inaccuracies, need their own allocations; the budget cannot be spent twice.

For a worked example, assume—not measure—the per-round scaling law

\[p_L(d)=A\left(\frac p{p_{\mathrm{th}}}\right)^{(d+1)/2}\]

for odd-distance rotated patches. Set A=0.1, p=10⁻³, pth=10⁻², N=10⁸ block-round opportunities, and ε=0.01. Here pL is failure probability per block per correction round; N already sums rounds over all logical blocks. The target is pL≤10⁻¹⁰. Substitution gives 10^(−1−(d+1)/2)≤10⁻¹⁰, hence d≥17. At d=17 the model exactly exhausts this budget; choosing d=19 would leave a factor-ten margin within the model.

A distance-17 rotated patch has 17²=289 data qubits and 288 dedicated check ancillas in the minimal count used earlier, totaling 577. One hundred such patches would use 57,700 qubits before routing, spare capacity, logical-operation space, or magic-state factories. This is an illustrative arithmetic result, not a hardware requirement forecast. Its value lies in making every assumption inspectable.

If pL instead referred to a logical gate lasting several rounds, N would have to count gates. Mixing those units can change an estimate by orders of magnitude. Write “per what?” next to every error probability and every time estimate before comparing architectures.

Worked check 10.2. What total failure bound does the same model give at d=19?

Reasoned solution

The per-block-round probability is 10⁻¹¹, so NpL=10⁸×10⁻¹¹=0.001. The minimal patch count becomes 2(19²)−1=721 qubits. This buys margin only within the assumed scaling model.

10.3 A reproducible resource study

10.3.1 Report what the model establishes

Build a small resource-estimation study around the preceding example. Choose a range of physical error probabilities below the hypothetical threshold, solve for the smallest odd distance meeting a fixed budget, and tabulate distance, data qubits, check ancillas, and block-round volume. Then vary N or ε one at a time. The discrete jumps in distance are real features of the chosen model, while its parameters remain assumptions.

Add a separate resource-state budget. If a computation uses M injected states and each fails with probability at most q, then Mq is a union-bound contribution. Include the acceptance yield from Chapter 9, factory throughput, storage while waiting, and space occupied by factories. If logical gates require patches to move, merge, or interact, account for their extra area and duration rather than treating every gate as a free single-patch operation.

The course verification script reproduces small code syndromes, CSS ranks, logical distances, parity extraction, injection branches, and the numerical estimates. Use it as a baseline. A complete project submission should specify its noise and circuit models, equations, decoder assumptions, executable calculation, endpoint checks, and uncertainty or sensitivity analysis. It should clearly separate exact finite-code certificates, theorem statements, numerical observations, and hypothetical planning models.

We began by asking whether an error could be identified without exposing an unknown state. That led to syndrome subspaces, algebraic correction conditions, local code geometry, controlled fault propagation, and a resource budget. Further study can now branch toward quantum LDPC codes, bosonic codes, device-specific noise, or decoder design. In each direction, keep the same discipline: identify the operational task, prove or verify the relevant claim, and state the assumptions that make it true.

Worked check 10.3. If M=10⁶ injected states receive a failure budget of 0.001, what per-state error target suffices?

Reasoned solution

q≤0.001/10⁶=10⁻⁹ suffices by the union bound. This allocation is separate from data-memory and Clifford-operation failure budgets and does not specify which distillation circuit can achieve the target.

Summary

  • Threshold arguments depend on a declared local noise model and fault-tolerant gadget construction.
  • A computation needs a total error budget with consistent per-round or per-gate units.
  • Resource estimates must include yield, time, factories, and omitted architecture costs—not only data qubits.

1. Quick check §

What total-failure bound follows from N opportunities each bounded by pL?

Hint 1

Use the union bound.

Worked solution

The probability of at least one failure is at most NpL, capped trivially by one. Independence is not needed.

2. Quick check §

What is the suppression condition in the illustrative recurrence pₗ₊₁≤Apₗ²?

Hint 1

Inspect Ap in the iterated expression.

Worked solution

Ap<1 ensures the upper bound shrinks with concatenation level, assuming the recurrence applies at every level.

Hint 1

Square the current bound and multiply by 100.

Worked solution

The upper bounds are 10⁻⁴,10⁻⁶,10⁻¹⁰. They are model bounds rather than measured logical error rates.

Find the per-opportunity target for N=10⁷ and ε=0.001.

Worked solution

The sufficient target is 10⁻¹⁰ per opportunity.

If a state factory produces 1000 accepted states per second and M=10⁶ are needed, what throughput-only time bound follows?

Hint 1

Divide demand by accepted-output rate.

Worked solution

At least 1000 seconds of factory production are needed. Parallelization, preproduction, buffering, and computation scheduling determine the actual wall-clock runtime.

8. Misconception §

Is a quoted threshold meaningful without a noise model?

Hint 1

Ask what faults and correlations it covers.

Worked solution

Not as a reliable prediction. A threshold belongs to specified codes, circuits, noise assumptions, and decoding; changing these can change the applicable value.

9. Misconception §

Does the 57,700-qubit estimate describe a complete computer?

Hint 1

List the omitted resources.

Worked solution

No. It counts only one hundred minimal distance-17 patches under a hypothetical scaling model. Routing, logical gates, factories, spares, scheduling, and model uncertainty remain to be included.

10. Extension §

Design a sensitivity study that avoids presenting the model as hardware data.

Hint 1

Vary one assumed input at a time and keep units fixed.

Worked solution

Sweep physical error p below the assumed pth, solve the smallest odd d for a fixed N and ε, and report patch counts. Repeat for several A values and budgets. Label every curve hypothetical and state that no numerical fit or hardware validation has been performed.
