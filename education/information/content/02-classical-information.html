We can now describe what a receiver knows. Probabilities record his expectations before an observation, conditioning updates them afterwards, and the best decoder follows from the updated numbers. All of that concerned a single card and a single report.

Real messages are long, and real channels are used many times. Two questions follow that one report cannot answer. How many bits does it take to describe what a source produces? And how many bits can pass through a noisy channel per use? To answer them we first need joint probabilities for pairs of values, and independence for repeated uses. Counting the likely messages then gives entropy, the cost of description. Adding noise forces redundancy, and comparing what a channel output reveals with what it leaves uncertain gives the rate a channel can carry.

2.1 Probability and Correlation

A channel takes an input value and produces an output value, so we must describe two uncertain values at once. How should we describe a pair, and when does one value tell us about the other? We start from a noisy wire and tabulate its input–output pairs. Reading the table in different directions gives the joint, marginal and conditional probabilities. Asking when the output tells Bob nothing then defines independence, which is the assumption that lets us treat long messages.

2.1.1 Joint and conditional probabilities§

Alice sends one bit to Bob through a wire. She chooses 0 and 1 equally often. The wire is noisy: on one quarter of uses it flips the bit, whatever the bit was. Bob reads the output. What does the output tell him about the input?

We count, as we did with the cards. Imagine 8 uses in the model's proportions. Alice sends 0 four times; one of those is flipped, so three arrive as 0 and one as 1. The same happens to her four 1s.

We need names for the uncertain values. Let \(X\) stand for the input and \(Y\) for the output. A lowercase letter names a particular value: \(x\) can be 0 or 1. An uncertain value with given probabilities is called a random variable.

Each cell of the table divided by 8 is the probability that both things happen. This is the joint probability \(p(x,y)\):

\[p(0,0)=p(1,1)=\tfrac38,\qquad p(0,1)=p(1,0)=\tfrac18.\]

How often does the output equal 0, whatever the input was? We add the first column, \(3/8+1/8=1/2\). In symbols, \(p(y)=\sum_x p(x,y)\), where the sum runs over the allowed inputs \(x=0\) and \(x=1\). A probability obtained this way, by adding over the value we ignore, is a marginal probability.

Now Bob sees output 0. As with the red lamp, he keeps only the trials consistent with what he saw. Of the 4 trials with output 0, 3 had input 0. So \(p(X=0\mid Y=0)=3/4\). In general the conditional probability is

\[p(x\mid y)=\frac{p(x,y)}{p(y)}\qquad(p(y)>0).\]

The wire itself is described by conditional probabilities in the other direction. Given input \(x\), it gives the same bit with probability \(1-e\) and the flipped bit with probability \(e\). Here \(e=1/4\). This wire is called a binary symmetric channel. Rearranging the conditional rule gives \(p(x,y)=p(x)\,p(y\mid x)\): Alice's choice probability times the wire's response. For example, \(p(0,0)=\tfrac12\cdot\tfrac34=\tfrac38\).

The table also exposes a trap. Taken separately, the input and the output each look like a fair coin. Yet they agree on 6 of every 8 trials. So the two marginal distributions do not determine the joint one. A wire that ignored its input and printed a fresh fair coin would have the same marginals and no agreement beyond chance.

2.1.2 Independent and correlated messages§

The coin-printing wire suggests a question. When does the output tell Bob nothing at all about the input?

Seeing \(y\) tells him nothing exactly when it leaves his probabilities unchanged: \(p(x\mid y)=p(x)\) for every \(x\) and \(y\). Multiplying both sides by \(p(y)\) turns this into a condition on the joint table,

\[p(x,y)=p(x)\,p(y).\]

Two random variables satisfying this for every pair of values are independent. Otherwise they are correlated.

Test our wire. With \(e=1/4\), \(p(0,0)=3/8\) but \(p(0)p(0)=1/4\), so input and output are correlated. Now let the wire flip with \(e=1/2\). Every cell becomes \(1/4\), which equals the product of the marginals. The output is then independent of the input, and Bob may as well not look. At the other extreme, with \(e=0\), the pair is 00 or 11 with equal probability. Each bit alone is still fair, but reading one removes all uncertainty about the other.

Independence matters most when a source is used many times. Suppose a source emits 1 with probability \(1/4\) and 0 otherwise, and suppose each emission is independent of the others. Then probabilities of strings multiply. The string 0010 has probability \((3/4)^3(1/4)=27/256\). Without that assumption we could not compute it from the single-symbol probabilities.

The assumption is substantive. A source with memory might tend to repeat its last symbol, so that 0000 and 1111 are more likely than the product rule says. Our results about long strings all assume independent, identically distributed uses. A source with memory needs its own analysis.

Problems

Problem 2.1. For the fair-input flip channel with e=1/4, what is p(X=0 | Y=0)?

Worked solution

The joint probability is 3/8 and the output-zero probability is 1/2. Dividing gives 3/4. A fair output does not mean the input and output are independent.

2.2 Entropy and Compression

We left the cards with an unmeasured uncertainty. Now that probabilities can be assigned to whole strings, we can ask how many bits a description costs. We start from equally likely messages, where counting yes-or-no questions gives a logarithm. Unequal probabilities then give each message its own cost, and averaging the cost gives entropy. Finally, long strings from an independent source show that entropy is also the rate at which such strings can be compressed.

2.2.1 Information content and average length§

Suppose Alice picks one of 8 equally likely messages. How many yes-or-no questions does Bob need to identify it? Each well-chosen question splits the remaining candidates in half: 8, then 4, then 2, then 1. So he needs 3 questions, and Alice can send the 3 answers as 3 bits.

With \(N=2^k\) equally likely messages the same halving takes \(k\) questions. The number \(k\) with \(2^k=N\) is the base-two logarithm, written \(\log_2N\). So \(\log_28=3\), and \(\log_2 1=0\): one certain message needs no questions.

What if the messages are not equally likely? Take four messages A, B, C, D with probabilities \(1/2,1/4,1/8,1/8\). A fixed two-bit label for each costs 2 bits. Can Bob do better on average? He can first ask "Is it A?". Half the time the answer is yes, and he is done after one question. Otherwise he asks "Is it B?", and if not, "Is it C?". Writing yes as 0 and no as 1, the answer records are

\[A\to0,\qquad B\to10,\qquad C\to110,\qquad D\to111.\]

The average number of bits is \(\tfrac12\cdot1+\tfrac14\cdot2+\tfrac18\cdot3+\tfrac18\cdot3=\tfrac74\), which beats 2.

Look at the lengths. A message of probability \(1/2\) took 1 bit, one of probability \(1/4\) took 2, and one of probability \(1/8\) took 3. In each case the length is \(-\log_2p\). This number is the information content of an outcome of probability \(p\). Rare outcomes carry more of it. It also adds correctly: for two independent outcomes the probabilities multiply, so their information contents add.

The average information content of a source is its entropy,

\[H(X)=-\sum_x p(x)\log_2p(x).\]

A term with \(p(x)=0\) counts as zero, since an impossible message costs nothing on average. For our four messages \(H(X)=7/4\), exactly the average length of the question code. That exact match happens because every probability is a power of one half, so every \(-\log_2p\) is a whole number. For other probabilities the lengths must be rounded up, and a one-symbol code can only come close.

Can any code do better than \(H(X)\) on average? We quote the answer without proof: no code that can be decoded without ambiguity has average length below \(H(X)\). This is part of Shannon's source coding theory.

Why did we need the question structure at all? Bob receives a stream of bits with no spaces. A first 0 completes A. A first 1 means more is coming; 10 completes B, while 11 needs a third bit. He can split the stream as it arrives because no codeword begins another codeword. A code with this property is a prefix code.

2.2.2 Repeated sources and compression limits§

Return to the source that emits 1 with probability \(1/4\). Its entropy per symbol is

\[h_2(\tfrac14)=\tfrac14\log_24+\tfrac34\log_2\tfrac43\approx0.5+0.3113=0.8113\text{ bits}.\]

For any binary source we write \(h_2(q)=-q\log_2q-(1-q)\log_2(1-q)\), the binary entropy. But a single symbol cannot be sent in 0.81 of a bit. One symbol needs a whole bit, so the question code gains nothing here. Can long strings do better?

Suppose the source runs \(n\) times, with independent uses. A long string will usually contain about \(n/4\) ones. That a long run's fraction of ones settles near its probability is the law of large numbers, which we quote as a standard result of probability theory. Call strings with about \(n/4\) ones typical.

How likely is one typical string? Its probability is a product of \(n/4\) factors of \(1/4\) and \(3n/4\) factors of \(3/4\). Taking \(\log_2\),

\[\log_2p(\text{string})=\tfrac n4\log_2\tfrac14+\tfrac{3n}4\log_2\tfrac34=-n\,h_2(\tfrac14).\]

So each typical string has probability about \(2^{-nh_2(1/4)}\). The total probability of all typical strings is at most 1. Hence there are at most about \(2^{nh_2(1/4)}\) of them. Alice can number them and send the number, which takes about \(nh_2(1/4)\approx0.81n\) bits instead of \(n\). The rare atypical strings can be sent with a flag and the full string, or declared a failure.

How rare is "rare" for small \(n\)? With \(n=3\), strings with zero or one 1 have total probability \((3/4)^3+3(1/4)(3/4)^2=54/64\approx0.84\). The atypical strings still carry 16% of the probability. The saving only becomes reliable as \(n\) grows.

Shannon's noiseless coding theorem makes this precise for independent repetitions: any rate above \(H\) bits per symbol can be reached with failure probability tending to zero, and no rate below \(H\) can. We cite this theorem and have only shown the counting behind it. It is a statement about long blocks. It does not say that one biased bit fits into 0.81 of a physical bit.

2.3 Noisy Communication

Compression removes redundancy because the source is predictable. A noisy wire pushes the other way: to survive flips, a message seems to need extra bits. How much extra? We first protect one bit by repeating it and compute what that costs. Then we ask how much one channel output reveals about its input. That quantity, the mutual information, sets the rate a channel can carry reliably.

2.3.1 Channels and decoding§

Alice's wire flips each bit independently with probability \(e\). How can she make Bob's error smaller than \(e\)?

A first attempt is to send each bit three times: 0 as 000 and 1 as 111. Bob takes a majority vote. One flip is outvoted, so Bob fails only when two or three positions flip.

Why does three-fold repetition help, and by how much? There are three ways to flip exactly two positions: 110, 101 and 011. Because flips are independent, each has probability \(e^2(1-e)\). Flipping all three has probability \(e^3\). These four events cannot happen together, so their probabilities add:

\[p(\text{fail})=3e^2(1-e)+e^3=3e^2-2e^3.\]

At \(e=0.1\) this is \(0.027+0.001=0.028\), well below 0.1. The coefficient 3 counts the positions, and the independence assumption is what let us multiply.

The improvement has a price. Three uses of the wire now carry one bit of Alice's message. The rate of a code is the number of message bits divided by the number of channel uses, here \(1/3\). Repetition trades rate for reliability.

2.3.2 Reliable transmission and rate§

Longer repetition codes make the error smaller still, but their rate falls towards zero. Must reliable communication always cost more and more uses per bit?

To answer, we first ask how much one output tells Bob about one input. Before looking, his uncertainty about a fair input is \(H(X)=1\) bit. After seeing \(y\), the input is the same bit with probability \(1-e\) and the other bit with probability \(e\). His remaining uncertainty is \(h_2(e)\), whichever \(y\) he saw. The average uncertainty left after reading the output, \(H(X\mid Y)=\sum_y p(y)\,H(X\mid Y=y)\), is the conditional entropy. Here it equals \(h_2(e)\).

The reduction in uncertainty is the mutual information,

\[I(X:Y)=H(X)-H(X\mid Y)=1-h_2(e).\]

At \(e=1/4\) this is about \(0.19\) bits per use. At \(e=1/2\) it is zero, as it must be, because then input and output are independent. At \(e=0\) it is one full bit.

Does this number say anything about codes? Shannon's channel coding theorem says it does, and we quote it here. For independent uses of the binary symmetric channel, every rate below \(1-h_2(e)\) can be reached with block error tending to zero as the blocks grow. No rate above it can. This limit is the channel's capacity. For a general channel the capacity is the largest mutual information over input distributions; for this symmetric channel the fair input achieves it.

So the answer to our question is no. Long, cleverly designed codes keep a fixed positive rate while their error vanishes. Repetition is not such a code: it lowers the error, but at a rate that shrinks to zero. Our calculation evaluated one input distribution and one code. The theorem's proof needs a coding argument that lies beyond this course.

Every rule so far added probabilities of alternatives that exclude one another. Is every uncertainty about a physical carrier of that kind?
